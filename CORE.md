**Current audit controls (AUDIT-v1 / SCV-v14).** [AUDIT_REVIEW_PROTOCOL](AUDIT_REVIEW_PROTOCOL.md) governs assigned research roles, opponent-strength checks, measured availability versus separate sensitivities, actual data sufficiency, source access, native fixture identity, final-mini handovers and effective first-play reviews. New numeric cards require the hash-bound contract review. These owner-directed controls do not establish predictive improvement or relax ASSESS-100.

**MDS-2026.11.15-v24.18 · CR-2026.11.15-R2 · P-2026.11.15-v24.16 · SCV-2026.11.15-v14 · SEL-2026.10.22-v4.** The one document a game card must read in full before research, with the [prompt 1 core](research/prompts/1_GAME_CARD.md) and the one [sport file](research/prompts/1_sports/). It condenses the rules that decide a card; everything else is reference, read when the card touches that topic. Where this page and a long-form protocol differ in wording, the protocol governs and the difference is a defect to report (GOV-v2). Where a pre-v24 sentence anywhere contradicts this page, this page governs for cards under P-2026.10.22-v24.0 and later; earlier cards keep their own method.

**Reading receipt.** Print branch, HEAD SHA, read time with offset, every uncommitted control difference, and the files actually read: this page, the prompt 1 core, the sport file and whatever the card opened. Never claim a file was read in full from an excerpt.

## 1. Honesty and custody

- Everything is Markdown, CSV and text. Code lives only under `ml/` and is run, never described. Do not claim a grid, simulation, fit, calculation, file write, readback, commit or push that did not happen; report the exact error if one failed.
- Labels are literal. The analyst's own final probability is `ANALYST_PRIMARY_V1 / UNCALIBRATED_ANALYST_PRIMARY`, built from a frozen reference plus logged adjustments from P-2026.10.22-v24.0; cards before it keep their method. Nothing is certified; a model is `EXPERIMENTAL_NOT_QUALIFIED`.
- **Permanent historical closures (owner instruction,9November2026).** Before any historical settlement/research retry, consult [PERMANENT_CLOSURES.csv](research/historical_resolution/PERMANENT_CLOSURES.csv). Its nine exact corner contracts are `UNATTAINABLE / COMPLETELY_RESOLVED / DO_NOT_RETRY`: no future attempt, automatic reopening, due-date task or sporting-grade inference. This owner-directed exception supersedes older UNRESOLVED/retry instructions for those keys. Exclude them from sporting scores and model labels. P126/P418 operational items are closed at their documented evidence limits; consult the [current historical dispositions](research/verification/historical_gap_resolution_2026-11-09-1/REPORT.md). The three additional unattainable period/corner fields in that report are terminal and must not be automatically reopened. [Closure authority](research/verification/historical_closure_2026-11-09-1/OWNER_CLOSURE.md).
- Missing is not zero. Use `NOT_COMPUTED`, `NOT_ESTIMATED`, `NOT_VERIFIED`, `UNKNOWN_DEFINITION`, `N/A` exactly. Missing evidence is `UNRESOLVED`, never VOID, a loss, a healthy player or a clean sheet. Never invent a source, time, probability, baseline, lineup or score.
- Issued cards, settled originals, previous log parts and dated reports are immutable. A correction is a dated addendum with its parent, reason and affected keys. A card's frozen reference and picks are never edited after issue.
- **SRC-ALT-v3 (2026-11-11).** Check first, then open. A page is judged by the rules for the reader that opens it: Claude-User for the repository agent, ChatGPT-User for a research chat, all eight agent names for any script or bulk download. A page blocked for its reader, or whose rules cannot be read, is not opened or worked around; a permitted alternate is found for the same fields (`python -m ml source-audit --url U --reader R`; [SOURCES](SOURCES.md)). A site's own terms apply as well as its robots rules. Social posts follow SOCIAL-v2; a page no agent may open reaches a card only as an owner capture (OWNER-CAPTURE-v1), one source.
- **SPORTS_ONLY / MARKET_BLIND.** No odds, line movement, tips, previews, prediction markets or fantasy inputs in research, the reference, adjustments or any card. A supplied line is contract metadata. The only market-adjacent items are the line-implied 0.5 written into supplied two-way rows and the hand-entered post-settlement benchmarks ([BENCHMARK_PROTOCOL](BENCHMARK_PROTOCOL.md)); neither is read before settlement. The decision lab stays firewalled ([RULES_REFERENCE](RULES_REFERENCE.md#5-sources-event-state-and-time) Part A §5a); no staking, edge or value claim; no in-play automation.
- Every run that changes files ends with a commit and push by exact path, no force, then a check that `HEAD` equals `origin/main`. Never stage the whole tree.

## 2. Identity, the mini and IDs

- A game card is appended to the active mini (`research/active_minis/`) before the footer, with its intake row and footer updated, read back and committed. One issuing writer per mini; only the lease holder appends; a frozen mini accepts nothing.
- Events use a stable **local key** `LOCAL-<MINI_KEY>-G####`. No canonical P-ID is assigned or reserved before settlement; prompt 3 settles the event and runs the prompt-4 import, which assigns the ID and records the local-to-canonical map. P-518 to P-522 are never reused.
- Search every mini and log by native ID, aliases and participants before writing; an existing event gets a dated addendum, not a second card. A doubleheader needs its game number or native ID.
- **External research lanes (EXT-v3, 2026-11-11).** The owner's research chats share one **event key** (`EV2-<native-identity digest>`, `python -m ml external event-key`), each works one lane at a pinned commit, and returns one LANE_RETURN block. Prompt 1 merges them here and makes one card; only that card is scored ([EXTERNAL_RESEARCH_PROTOCOL](EXTERNAL_RESEARCH_PROTOCOL.md)).
- Preserve line endings and every earlier byte; compare the destination prefix after the append. Re-read HEAD and the destination's byte count and tail immediately before each write.

## 3. A card, step by step (v24)

1. **Read** this page, the prompt 1 core, the sport file; print the receipt. Resolve the event: competition, season, stage, participants, venue, native ID, scheduled start in venue zone, UTC and Australia/Sydney; the endpoint and settlement conventions (overtime, extra time, shootout, retirement).
2. **Tier.** `python -m ml reference tier --competition C` (A, B or C; [REFERENCE_MODEL_PROTOCOL](REFERENCE_MODEL_PROTOCOL.md)). Print it.
3. **Reference, before any probability is typed.** No fitted model is a card reference until it is promoted (ML-SEP-v1, §7); with a promotion, `python -m ml pregame reference …`. TB-2-MD or TB-1-MD: `python -m ml reference standings …` then `python -m ml reference run …`. Baseline only: `reference run` without standings. The NHL and MLB (count sports) take the league baseline from `python -m ml baseline`. Paste the Reference block into the card. If the request is too late for the full card to finish before the start, issue the **fast card** first (FASTCARD-v1) and the full card after as an addendum.
4. **Research** by the sport's value-ranked checklist ([RESEARCH_CHECKLISTS](RESEARCH_PROTOCOL.md#part-d-research_checklists)): availability and starters first, timed to when they are published, then history windows (starting from `python -m ml history-pack` where the repository holds the competition, then the later games online), conditions, rules. With external lanes, their merged evidence (`python -m ml external merge`) is this step's input. Decisive facts need a source, a publication time, a retrieval time and a second independent source; a projection is not a confirmation. Search all of it until the horizon, record every attempt.
5. **Adjust.** One ledger row per confirmed fact with its [effect-table](PARAMETERS.md#part-b-effect_tables) row and entry size ([ADJUSTMENT_LEDGER_PROTOCOL](ADJUSTMENT_LEDGER_PROTOCOL.md) section 1). Apply them to the reference centre, recompute one score grid, read every supplied contract from it. Width never below the [floor](PARAMETERS.md#part-a-competition_parameters).
6. **Picks block.** `PICKS_V2` for every priced contract ([CARD_AND_LOG_TEMPLATES](CARD_AND_LOG_TEMPLATES.md) section 3c), with `rank_scope` (FREEZE-v1: SUPPLIED_ONLY unless the request says "all lines") and, for an external event, `event_key`, `external_runs` and `external_disagreement`; then `python -m ml card lint --mini M --key K` until it passes; then `python -m ml ledger add …`.
7. **Write** the card (decision block, picks block, adjustment table, appendix A1-A9), update intake and footer, read the file back, run `python -m ml pregame run …` (freezes the card's own p and runs any release as a separate shadow), write the learning log (`python -m ml learning-log init` then `check --stage pregame`, LEARNLOG-v1), commit and push before the scheduled start whenever possible.
8. **Return** the picks, the winner, the reasons and sources, the reference, the adjustments with their sizes, the abstain flag, the gaps, the local key, timing and the commit.

**What a card says.** A probability for every supplied contract; the winner for both sides (with a draw where allowed); a most-likely list of up to four rows with each row's distance from the centre; an information list (rows moved at least 0.03 from the reference); and `no strong pick` when no ranked row reaches 0.65 and no row moved. Rule T2 is a descriptive count; the headline is the paired proper score. A pair that covers itself counts as one pick.

## 4. Contracts, masses and settlement vocabulary

- State each contract's unit, period and action (regulation, overtime, extras, push, void, retirement) before pricing. Basketball: every line includes overtime unless its own text names regulation or a segment (BK-OT-1, CR-2026.11.07-R1). Australian rules finals: every line includes extra time on the same terms (AFL-ET-1, CR-2026.11.10-R2). An ambiguous text is priced under every reading, frozen with both, and queued; never resolved silently.
- All contracts come from **one** coherent distribution. Keep W, P (push) and L masses; `p = W/(W+L)`; masses sum to one. A winner row in a competition with draws loses on a draw unless the contract says otherwise. Complementary rows agree. Apply a key-number, push or tie adjustment to the whole normalised distribution, never to one row. Do not clip a probability; a ranked row is at or below the 0.90 selection ceiling and a higher true value is kept outside the ranked list.
- Family rules ([RULES_REFERENCE](RULES_REFERENCE.md#part-b-selection_rules) Part B §4) apply unchanged: soccer first-half Over 0.5 needs a half-specific model, baseball +1.5 at rank 1 needs p at least 0.65, tennis games come from the complete set-score states, corners need a named provider and a count model, period and player rows need exact definitions and a source.
- Grades: WIN, LOSS, PUSH, VOID (only under a frozen void rule), UNRESOLVED. Evidence: A official field owner for the exact target; B structured provider with lineage disclosed; C single secondary; E a bound that grades only if every feasible value agrees; X none. Settle from a box score or linescore with a sum check, never from a headline, recap title or narrative article. Corrections append revisions with parents; a conflict leaves keys UNRESOLVED.
- Every open item has an actor, a route, a due time with timezone, a final-time basis, a last attempt, and a scheduled-automation status (R38). Nothing is automated unless it is.

## 5. Evidence and timing

- **Horizon.** The game-log scheduled start, unless an earlier actual issue or verified first play. Research may finish after the start; label the card `PREGAME`, `PRE_START_RESEARCH` (TIMING-v3: research began before the actual start, with a declared research start, a not-started observation and no outcome exposure; scored with `PREGAME`), `POST_START_ISSUE` or `TIMING_UNVERIFIED`, and `CLEAN_PRE_START_INPUTS` only with proof that no outcome was seen. A late page is never pre-start evidence by itself. Record the horizon, retrieval, completion, last availability check and actual issue separately.
- **Availability.** Starters and roles, selected bench, injuries, illness, suspensions and late changes for **both** sides, from the official match record, both clubs, medical or eligibility sources and permitted structured providers, with local-language discovery for obscure competitions. A failed extraction is not non-publication. "No injuries found" is not "none".
- **History.** Each side's L5, L10, L15 and L20, season and league from dated games before the horizon, with true n, opened sources and exclusions of duplicates, awards and forfeits. The windows overlap and are one piece of evidence; a short-window swing is width, not a lean, unless a named current mechanism explains it. The framework found no bounce-back or streak effect in six leagues.
- **Corroboration** (EXH-v1): any missing, partial, stale or conflicting required field is pursued through alternative sources before it is called a gap; domain count is not independent-source count.
- **Weather** for outdoor play: the venue-local forecast for the match window (the 30-60 minutes around the start, during and after), not a morning forecast. Downgrade only for weather in the window.
- **Known-at.** A historical row's date is not its availability time; an input whose availability before the horizon cannot be shown is `KNOWN_AT_UNVERIFIED` and may not decide a ranked row.

## 6. Probability

- Start from the reference. A departure needs a ledger row; a feeling is not a row. Do not count an effect already in a rating. The reference and the league-only `BASELINE_P` (RULES_REFERENCE Part B §9) are printed beside every number; a missing baseline uses an enumerated reason.
- **Widths** are never below the competition's floor without a written exception. Early season, stale profiles and unconfirmed lineups widen or mix, they do not narrow. A lineup uncertainty is a declared mixture with weights frozen before pricing.
- **Structure.** NFL margins of 3 and 7, hockey one-goal finishes and empty nets, baseball extras and walk-offs, cricket collapses and tennis match-level form shocks are handled explicitly ([SIMULATION_PROTOCOL](SIMULATION_PROTOCOL.md)). Basketball overtime is played as real extra periods of scoring for both sides (OT-PERIODS-v1, 2026-11-11), not a one-point bonus. A league name selects reference constants only inside its own sport (LEAGUE-KEY-v2). Research chats price with the kit (`ml/kit/sr_kit.py`, KIT-v1), whose receipts are re-run here. Simulate only where its table says, in code, with seed, N and Monte Carlo error printed. The exact method is the default.
- **Easy lines.** Report each ranked row's distance from the centre. A near-certain analyst-chosen alternative line is label-only evidence. A hit rate is not skill; the line-implied 0.5, the baseline, the reference and any benchmark are the comparators.
- **Abstain** below 0.65 with nothing moved. Stated probabilities between 0.40 and 0.65 have not separated winners from losers in the card record (slope 0.15, SE 0.31, 525 rows).

## 7. Models and learning

- **MLSCOPE-v3.** Models run where they are needed. Tier A: the release's model is frozen before the card as the declared reference, or as the challenger when another reference is declared; the card then starts from the frozen reference and its departures are scored. A model is judged only on frozen, pushed, pre-start rows, after at least 8 settled weeks and 50 settled paired games, against the reference on identical rows. A release is frozen for a season; edits outside the cycle's import closure never retire it. Prompt 8 owns every `ml/` change and every promotion.
- **No reinforcement learning in forecasting.** Outcomes do not depend on a forecast. The online expert weighting at settlement is called online learning.
- Prompt 3 settles the card, then the shadows, then runs the import. Prompt 6 ingests verified outcomes and evaluates; prompt 7 builds data; prompt 8 changes things. The league-day lane freezes every fixture of a competition with a release, card or not.
- Learning data are verified finals with sources and known-at times; a fact captured today is known today, never retroactively.
- **One model per sport, judged on held-out competitions (POOLED-v1, 2026-11-11).** Bulk open history (`research/bulk_history/`, BULK-v1) feeds studies that choose a sport's settings on some competitions and judge them on others. A study's result changes a reference only through its pre-registered rule, and a fitted model still stays separate until promoted (ML-SEP-v1).

- **Fitted models are kept separate (ML-SEP-v1, owner instruction 9 November 2026).** Until a model has shown it improves the predictions, its predictions stay separate from the rest of the framework. A competition without an evidenced row in [ML_PROMOTIONS.csv](research/model_registry/ML_PROMOTIONS.csv) never takes a fitted release as its reference: the tier rule falls back to TB-2-MD, TB-1-MD or the league baseline. `pregame reference` refuses to run, the picks block carries `model_p NONE` (the linter rejects a number), and the card's Model shadow block shows status and receipt only. The model still runs after the card (`pregame run`) and in the league-day lane, into its own shadow ledger, where it is scored against the card and the reference on identical rows. A promotion row needs a lane at its decision floor (50 settled paired games and 8 settled weeks) with a paired interval below zero, and the owner's decision (prompt 8).
- **Learning log (LEARNLOG-v1, owner instruction 9 November 2026).** Every new card gets a structured, point-in-time log in [research/learning_log/](research/learning_log/README.md): identity, contracts, the sport's required features for both sides (each with its source and known-at time, or MISSING with the reason), availability, prior games, and, at settlement, the outcome and grades. `python -m ml learning-log check` enforces it, and `build` turns the logs into the training dataset for later models.

**EXT-v3 operational scope.** [Current external protocol](EXTERNAL_RESEARCH_PROTOCOL_V3.md) governs manifest-bound multi-chat work: explicit reduced/six-lane modes, numeric-or-unpriced coverage, evidenced delay amendments, original retrieval clocks for undated pages, source-only refreshes and pre-exposure SINGLE comparison. Omitted work and unsupported contracts stay visible; a reduced card never enters the five-role cohort. The v24.15 owner-authorized baseline correction loads measured soccer rows; TEAM-CENTRE-v1 remains a shadow candidate. No player/weather effect or failed simulator is promoted.

## 8. Change control (GOV-v2 / STATFREEZE-v1)

- **FREEZE-v1 (owner instruction 2026-11-11).** After this owner-authorized v24.15 correction, source-only audited refreshes do not change the method version. No statistical or selection rule changes until the first 100 eligible fully settled paired games have been assessed, with no minimum weeks or completed-week wait, except bug fixes that change no output and owner-ordered corrections; the headline ranking count uses supplied lines only (`rank_scope: SUPPLIED_ONLY` unless the owner asks for all lines). The reason: every cohort so far has been 3 to 16 cards under a different policy, too few to judge any of them.
- **Statistical rules are frozen for a season.** A change to a probability method, a width, a selection constant, a reference or a release happens at a season boundary or through a new, separately scored lane. Bug fixes that change no output may happen at any time. Procedure changes are batched monthly. Editorial changes may happen at any time.
- **Every new rule names the rule it replaces** and the document that held it, and archives the replaced text byte for byte. No new paragraph is copied into a second document: others link to the one definition.
- Prompt versions: major for a format or statistical change, minor for a procedure change; wording keeps the version. The checks that can be code are code (`card lint`, `release-gate`, the tests); a hand-ticked checklist is for judgement only.
- Behavioural hypotheses are registered with a design, a metric and a stop rule before data ([HYPOTHESIS_REGISTER](HYPOTHESIS_REGISTER.md)); a favourable seed, a small sample or an exposed retrospective is not a test.

**EXT-v3 enforcement (CR-2026.11.11-R4).** See [the authoritative protocol](EXTERNAL_RESEARCH_PROTOCOL_V2.md). Legacy external check/merge is diagnostic only. Forecast/kit/profile identities remain v24.15; this release changes assessment policy only. [Current plan](research/external/EVALUATION_PLAN_v24.16.md).
