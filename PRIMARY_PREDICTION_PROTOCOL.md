## 1. What actually generates the primary rows

For each new game, complete independent sporting source/availability/contract research and declare the candidate recipe before pricing. Run the [primary runtime](ml/primary.py) against source-reviewed, hash-custodied, cutoff-safe normalized history. It fits two competition-specific team-rating models with different predeclared decay windows and a league-only comparator. A sports-only context-specific Exp3 bandit selects one entire fitted distribution; primary p_card, W/P/L, expected score and original ranks come from that selected distribution. The baseline remains a separate same-row comparator. This is **MODEL_ASSISTED_PRIMARY_V1 / EXPERIMENTAL_PRIMARY_NOT_CERTIFIED**, not manual-only analysis or a qualified production model.

The bandit is the RL integration: actions select the forecasting expert, not a stake or bet. It starts uniformly without feedback and records COLD_START honestly. Reward is 1 minus mean binary Brier on the original decisive top-two keys, learned only after final and feedback availability. It uses the actual logged selection probability in the importance-weighted update. Context separates policy, competition, endpoint, form-coverage bucket, timing phase and frozen recipe. Rewards from another context or not yet available do not alter the current action. No seed search after outcomes; an explicit seed is a research replay option. This is a contextual partition of Exp3, not a general deep-RL outcome model or evidence of performance improvement. [Algorithm reference](https://epubs.siam.org/doi/10.1137/S0097539701398375).

## 2. Runtime and input contract

Use the local checked-out version matching the card's authority receipt:

```text
python -m ml primary predict --request REQUEST.csv --history HISTORY.csv --contracts CONTRACTS.csv --out research/primary_predictions/EVENT_KEY
python -m ml primary predict --request REQUEST.csv --history HISTORY.csv --contracts CONTRACTS.csv --feedback EFFECTIVE_FEEDBACK.csv --out research/primary_predictions/NEXT_EVENT_KEY
python -m ml primary settle --bundle research/primary_predictions/EVENT_KEY --home-score HOME --away-score AWAY --final-at ISO_TIME --available-at ISO_TIME --evidence SOURCE_CAPTURE --evidence-sha256 SHA256 --out NEW_FEEDBACK_ROW.csv
```

Paths are explicit. A new immutable event/revision folder is required; reruns cannot overwrite issued bundles. Raw sporting captures stay outside the repository; admitted normalized market-free CSV and Markdown output may live only in the named primary folder or the named mini evidence scope. No canonical log/ID is written by the runtime. A remote/read-only agent without execution access must obtain a real bundle, or retain the research as NO_FORECAST / ML_NOT_RUN; never invent a model run, weights, probabilities or an RL update. An explicitly requested manual comparison stays separate, not silently substituted as the default primary.

REQUEST.csv has one row, columns `event_id,competition,home,away,cutoff,issue_at,actual_start,endpoint,outcome_exposure,candidate_recipe`, optional `venue`. Competition is the exact discovered archive path. All times have explicit zones. `outcome_exposure=NONE_RECORDED` is an operator declaration, not independently audited blindness. `actual_start` may be blank; timing then stays unverified. Issue is a declared timestamp; generated_at is recorded independently. A local timestamp/receipt cannot prove external pre-start publication. Never backdate an actual card to a research cutoff.

HISTORY.csv columns: `event_id,competition,endpoint,date,final_at,available_at,status,admission,source_url,evidence_path,evidence_sha256,season,home,away,hs,as_,reg_hs,reg_as,decision`; optional `stage`. One terminal event per row, no target or duplicate IDs. `status=FINAL`, `admission=RESEARCH_INPUT_REVIEWED` requires an actual human/source-field review; it is not an automatic owner-certification label. Every referenced capture must exist and match its measured SHA. Date <= final <= available <= cutoff; date-only/current-day uncertainty is handled conservatively by excluding same-UTC-day training games. Exact score endpoints/participants/source field meanings must be reviewed. Source hash comparison proves custody, not truth; retrospective archive dates alone are insufficient. No arbitrary extra/market columns accepted.

Cricket additionally requires `bat,bowl,venue,runs,legal_balls,wickets`, with full scheduled legal balls or all-out. Home/away coordinates represent batting/bowling teams and the full first-innings endpoint; settle as `(innings_runs,0)`. Never fit a full-innings model to shortened innings or derive a powerplay/second-innings/match-winner forecast from it.

CONTRACTS.csv columns: `contract_key,family,side,line,endpoint,definition,action`. Families `winner`, `handicap`, `total`; side HOME/AWAY/DRAW or OVER/UNDER. Winner action is explicitly THREE_WAY_DRAW_LOSES or DRAW_PUSH; other families require STANDARD_COMPLETED. Definition FROZEN_FRAMEWORK_CONVENTION is conditional sporting action, not verified operator terms. Record all supplied/derived candidate dispositions; semantic duplicates fail. Values above the selection ceiling stay diagnostic, never clipped. Existing family/gate/precision/unsupported-line checks still apply; the operator checks the complete candidate universe and prints the gate and joint, not a fabricated PASS. The runtime enforces the baseball +1.5 Rank1 floor but does not invent unavailable period models.

## 3. Scope, availability and actual use

Supported engines: fitted joint-normal team ratings for supported points sports, Dixon-Coles for soccer regulation, count ratings for supported hockey/baseball endpoints, limited-overs cricket full first innings. Each exact competition's endpoint/tie configuration governs; regulation scoring is fitted before adding extras once. The raw input must supply reviewed regulation/final fields. No generic NBA/NHL/MLB substitution for another league. Config DATA_HOLD warnings, unsupported engines, unknown participants, bad fit and wrong endpoint block numerical primary output. Tennis, field hockey, multi-day cricket, powerplays/player/period rows have no matching primary runtime here; research is retained with the exact NOT_IMPLEMENTED/NO_FORECAST reason, never falsely called ML-integrated. New adapters require their own tests and source contract.

For cricket, request home=batting side and away=bowling side; training home=bat, away=bowl, hs=runs, as_=0 (auxiliary), with integer legal balls/wickets within format limits. Cricket form means separately count batting runs and first-innings runs conceded; no chase score is inferred from the auxiliary zero. Both-side L5/L10/L15/L20 tables are generated with true n; shorter windows stay short. Ratings learn from prior team identity/scores/time decay. Current player availability, injuries, tactical changes and weather are mandatory sporting evidence but are **not fitted features of this first primary runtime**. Record their coverage and model limitation; do not claim the model quantified a lineup effect, or hand-edit p_card to imply it did. Material unsupported lineup/format regimes must be retained as qualitative/NO_FORECAST or trigger a separately versioned supported scenario model. Do not count correlated form windows repeatedly or append subjective model adjustments silently.

The request and cutoff determine admissible evidence, not a compulsory countdown. [Timing rules](TIMING_RESEARCH_PROTOCOL.md) still permit research after start with truthful input/issue separation; observed live/final outcomes block this full-event unexposed primary lane. Late-issued clean-input research is separate from genuinely pre-start-published prospective models. Old independently frozen shadow comparisons retain their own stricter timing requirements; no model independence is claimed for the new assisted primary cards.

## 4. Immutable model and feedback receipts

Bundle: FORECAST.md, PREDICTIONS.csv, GRIDS.csv (all three complete score distributions), FORMS.csv, HISTORY.csv, CONTRACTS.csv, REQUEST.csv, FEEDBACK_INPUT.csv, MODEL_CONFIG.csv and RECEIPT.csv. The receipt retains event/scope/endpoint, selected arm, full behaviour distribution, context, actual source-code-tree/input/output hashes, repository HEAD, library versions, exact discovered League config snapshot, fixed expert hyperparameter recipe, generated time and declared issue/cutoff, primary status and expected score moments. Verify all hashes, frozen W/P/L and p_decisive against the selected saved grid. Use PREDICTIONS directly as the A4/A5 numerical source; do not copy arbitrary old development predictions into a new game.

Settlement still researches official terminal fields and completes original R1-R12 first. Then `primary settle` verifies the exact original bundle, uses its original primary keys/probabilities, excludes pushes, computes reward and writes a new-only feedback row with final/source evidence hash. Source custody is not source-truth verification. Reconcile each canonical effective settlement revision and operator/definition before admitting a feedback row; preserve prior rows in the audit package and build a new effective-feedback inventory. Duplicate event feedback/branch conflicts block replay, never last-row-wins. All-push/no-decisive events get no artificial reward. Never update on pending events, target-event labels, future outcomes or unobserved counterfactual arm rewards.

Keep historical manual, MODEL_ASSISTED_PRIMARY_V1, model-shadow and staking/decision-lab cohorts separate. Only issued primary top-two rows count in their own T2 cohort; extra experts are comparators, not additional wins. Monitor same-row baseline-relative Brier/log loss, event/week dependence, calibration, actual starts, source coverage and field/endpoint errors. New training or policy versions create new receipts/context versions; preserve old issued forecasts. No practical-effect or sample-size acceptance is invented, and no production/performance certification follows from passing tests.

Owner authorisation changes the primary ML reading/execution gate; it does not remove source integrity, known-at checks, immutable originals or this market firewall.

Manual scenarios remain explicitly requested comparisons or qualitative sensitivity; they are not an unimplemented fitted availability model.
