# MDS-v8.0 Numerical Predictive Modeling Runtime

The **MDS-v8.0 Numerical Predictive Modeling Runtime** provides the core quantitative infrastructure underlying the repository's sports analysis and research standards.

---

## 1. Core Principles

1. **Event-First Distribution Modeling**: All contracts (Moneyline, Spread, Total, Double Chance, Draw-No-Bet, BTTS, Team Total) are derived strictly from a coherent underlying joint score probability distribution matrix $P(Y_{\text{home}} = s_1, Y_{\text{away}} = s_2)$.
2. **Mathematical Invariant Guarantees**:
   - Monotonicity: For any lines $L_1 < L_2$, $P(\text{Over } L_1) \ge P(\text{Over } L_2)$ and $P(\text{Under } L_1) \le P(\text{Under } L_2)$.
   - Covering Pair Consistency: $P(\text{Home } +k) \ge P(\text{Home ML})$ for all $k \ge 0$.
   - Probability Sum Rule: $P(\text{Over } L) + P(\text{Under } L) + P(\text{Push } L) = 1.0$.
3. **Point-in-Time Provenance & Leakage Protection**: Strict enforcement of $t_{\text{known\_at}} \le t_{\text{cutoff\_at}}$. Accessing any feature timestamped after the pregame cutoff immediately raises `DataLeakageError`.
4. **Chronological Rolling-Origin Splits**: Partitions data into sequential folds:
   $$\text{TRAIN} \longrightarrow \text{TUNE} \longrightarrow \text{CAL} \longrightarrow \text{TEST}$$
   Model weights are never fit on `CAL` or `TEST`. Probability calibrators (Platt scaling, Isotonic regression) are fit exclusively on `CAL`.
5. **Frozen D0 vs Independent H0 Separation**: The historical benchmark log D0 is permanently frozen for qualitative error taxonomy. Numerical models are trained exclusively on independent population H0 datasets.

## 2. Directory Layout

```
runtime/
├── pyproject.toml
├── README.md
├── config/
│   ├── selection_rules.json        provisional Rank-1 gate, Rank-2 rule, family rules, ladders
│   ├── regimes.json                measured regime multipliers (generated by research.operations.regimes)
│   ├── leagues/*.json              league scoring profiles (generated by research.operations.build_league_profiles)
│   ├── models/models.json, sources/sources.json, sports/*.json
├── src/
│   ├── common/    identity, provenance, contracts, endpoints, counts, splits, errors, leagues, artifacts,
│   │              calibration, calibration_layer, evaluation, uncertainty, prospective,
│   │              dixon_coles, strengths, ratings, distributional, stacking, boosting,
│   │              selection, snapshots, bigquery_ml
│   └── sports/    base.py and one package per sport: afl, baseball, basketball, cricket, nfl, nhl, nrl,
│                  soccer (engine, halves, corners), tennis
├── r_ingestion/   afl_fitzroy.R, nrl_nrlr.R (output registered with common/snapshots.py)
└── tests/         one module per component (engines, calibration, selection, snapshots, import smoke, ...)
```

`runtime/tests/test_import_smoke.py` imports every module, so a broken import fails collection instead of being skipped. Engines raise `FitFailed`, `InsufficientData`, `MissingInputs` or `NotFitted` rather than substituting a default; a zero score is a score, never a missing value.

## 3. Running the Test Suite

Current model builds are in `research/model_builds/runtime_h0_v2/`. The original
`runtime_h0/` directory is retained as superseded evidence. Build and verify with
`python -B -m research.operations.fit_runtime_models run` and `verify`.

The candidate generator defaults to a saved, fitted pipeline. A request supplies
the exact `sport`, `league`, verified `stage: "regular"`, a timezone-aware `cutoff_utc`, and `context` with
`home_team` and `away_team` matching archive names. It loads the engine and its
joint winner calibrator, refuses a mismatched endpoint, unavailable build, stale
code provenance or unknown team, and derives every row from the calibrated grid.
The pipeline's disjoint TRAIN/CAL/TEST ranges and artifact hash appear in the result.
Archive dates establish calendar cutoffs; they do not certify historical result-publication times, actual starts or current lineup freshness.
`SHADOW_ONLY` remains mandatory: winner temperature calibration is fitted only on
CAL and has no qualification implication for totals or handicaps. Too little CAL
data is labelled `IDENTITY_INSUFFICIENT_CAL`.

For an explicit research scenario with supplied expected scores, set
`mode: "analyst_explicit"`. Such a scenario is labelled
`UNCALIBRATED_ANALYST_SCENARIO`; it never silently replaces a fitted pipeline.

Example fitted request (save as JSON and pass to `research.operations.candidates`):

```json
{
  "sport": "soccer", "league": "EPL", "stage": "regular", "endpoint": "regulation",
  "cutoff_utc": "2026-10-09T08:00:00Z",
  "context": {"home_team": "Arsenal", "away_team": "Liverpool"}
}
```

This is a tooling example, not an issued fixture or forecast. Confirm the event,
participants, actual cutoff and current sporting evidence before using a card.

Execute pytest across the full repository test suite:
```bash
py -3.14 -B -m pytest -p no:cacheprovider research/tests research/operations runtime/tests -q
```
