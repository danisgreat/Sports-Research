# Contribution procedure

**Local keys until settlement; updated mini after every game (MINI-v2).** Apply [MINI_LOG_IDENTITY_PROTOCOL](MINI_LOG_IDENTITY_PROTOCOL.md). Research and mini creation (prompts 1–2) use stable local event keys and never assign or reserve canonical P-IDs. A canonical P-ID is assigned only in an event's settlement phase: prompt 3 settles the event and then runs the prompt-4 import, which assigns the ID. After each prompt-1 game request the repository agent appends the card to the active mini under `research/active_minis/`, updates intake and footer, reads the file back, and commits and pushes it. Preserve every owner-entered Upcoming game block and all earlier issued bytes. Formats: mini-log-10 / mini-settlement-10; earlier records retain their original formats.

**Persistent research and corroboration (EXH-v1).** Apply [RESEARCH_EXHAUSTIVENESS_PROTOCOL](RESEARCH_EXHAUSTIVENESS_PROTOCOL.md) to every required field in research, logging, settlement and verification. If a source is incomplete, open alternatives and verify material facts with another independent source; track every remaining field and attempt. Unresolved facts/corroboration never qualify as complete information. New settlements use mini-settlement-10 with a visible source-discovery/reuse section, three source/attempt/closure CSVs and S17; older originals retain their rules and bytes. Consult [RESEARCH_SOURCE_REGISTER](RESEARCH_SOURCE_REGISTER.md) and prior package registers, recheck actual coverage, and continue discovery beyond them.

**Online history and confirmed players (HIST-2026.10.16-v3 / AVAIL-2026.10.16-v4).** For every game, research both sides' L5/L10/L15/L20 online under [HISTORICAL_SOURCE_PROTOCOL](HISTORICAL_SOURCE_PROTOCOL.md), with opened sources, dated game rows and true n. Seek exact-game confirmed players, starting roles, bench/replacements and absences under [ROSTER_AVAILABILITY_PROTOCOL](ROSTER_AVAILABILITY_PROTOCOL.md); projected players remain unconfirmed. The retired local results store and its derived profiles are not required inputs or fallbacks. Earlier archive-first directions are superseded.

**Required repository fallback (REF-v1).** Always keep [https://github.com/danisgreat/Sports-Research/tree/main](https://github.com/danisgreat/Sports-Research/tree/main) as the standing reference. If required local files are not fully accessible (missing, unreadable, truncated or incomplete), retrieve the actual required contents from this repository before declaring them unavailable. Apply [GITHUB_REFERENCE_PROTOCOL](GITHUB_REFERENCE_PROTOCOL.md): resolve one main commit SHA, record exact files/read time and fallback results in the existing reading receipt, and preserve the declared authority mode. Never substitute an unpublished local mini, claim unread content or treat viewing code as executing it. If authorized remote access also fails, record the real gap and continue independent work.

**Google Drive (DRIVE-v2, optional).** The owner's [Sports Research Google Drive folder](https://drive.google.com/drive/folders/1ChlwkiOvd8c4MTaLC5BvkLniWogrm8Lj?usp=drive_link) is an optional drop box under [GOOGLE_DRIVE_EXCHANGE_PROTOCOL](GOOGLE_DRIVE_EXCHANGE_PROTOCOL.md). A chat that cannot write the repository may upload its complete updated mini to `uploads/<YYYY-MM-DD>/<label>/` for the owner to import. Nothing has to be pushed or mirrored to Drive, Drive is never a source of controls, and an upload is not a commit, freeze or canonical record. Controls come from the latest `main` branch on GitHub.

**ML/RL scope (MLSCOPE-v2).** Owner instruction, 22 October 2026: models run where they are needed, beside the analyst card and never inside it. Prompt 1 researches the game online and prices every p_card as ANALYST_PRIMARY_V1 / UNCALIBRATED_ANALYST_PRIMARY from one declared distribution ([PROBABILITY_TOOLKIT](PROBABILITY_TOOLKIT.md); code may do the arithmetic, with every input and step printed). Only after the card is written to the mini does prompt 1 run the pregame model shadow, which freezes the model and league-baseline rows, and the card's own p_card, on the same contracts when the competition has an active release, or records NOT_RUN_NO_RELEASE. Model output never changes a card's p_card, ranks or picks. Prompt 3 settles the shadow with the card; prompt 6 ingests and evaluates; prompt 8 builds releases and decides promotion. A model is judged only after at least 8 weeks and 50 paired games; a progress review falls due when either is reached first. RL has no forecasting role: online expert weighting updates at settlement. Details: [FORECAST_CYCLE_PROTOCOL](FORECAST_CYCLE_PROTOCOL.md). Supersedes MLSCOPE-v1, NOCODE-v1 and any older text that forbids code or models in prompts 1–5.

The repository holds Markdown, CSV and text only, with one exception: the maintainer model workshop `ml/` (Python source, tests and `requirements.txt`; CURRENT_RULES §0). Do not add code anywhere else, and never add JSON, notebooks, pickles, workflow files or binary data. A framework change is a change to documents; a workshop change must keep `python -m pytest ml/tests` passing, and any regenerated file under `research/model_shadow/` must come from an actual run whose receipt it carries. **Helpers and captures (2026-10-12, R07):** a script used to transform data, and raw captures (HTML pages, source CSVs carrying odds, API dumps), stay **outside** the repository folder. Record each capture's URL, capture time and SHA-256 in the change folder's receipt, and write the transformation rules out in prose in the dataset's `DATA_PROVENANCE.md`, so that a reader can check them by hand. Never stage a whole directory to "clean" a working tree, and never delete another writer's files; move unpublished work to a named quarantine folder outside the repository and list it there. Read [CURRENT_RULES.md](CURRENT_RULES.md) and [CURRENT_STATE.md](CURRENT_STATE.md) first. The pre-rewrite procedure is kept in [archive/superseded_2026-10-09/CONTRIBUTING.md](archive/superseded_2026-10-09/CONTRIBUTING.md).

1. **Inventory first.** Run `git status` and `git log -3`. Note branch, HEAD and any uncommitted work that is not yours. Preserve it; never overwrite unrelated edits.
2. **Preserve originals.** Never edit an issued card, a settled mini, a Combined Log above its end marker, a preserved original in `research/issued_research/`, or a dated verification report. Corrections are dated addenda. If a document must change, copy the old text into `archive/` in the same commit.
3. **Keep contracts explicit.** Identity, endpoint and time stay explicit. Never replace missing data with a guess or a q with a probability.
4. **Sources.** Use the routes in [SOURCES.md](SOURCES.md); record source failures and unknown independence. Keep odds-bearing material out.
5. **Check by hand.** Run the checklist matching your change ([VERIFICATION_PROTOCOL.md](VERIFICATION_PROTOCOL.md) §§2–6) and print evidence. A touched log must retain its entire original byte prefix with changes only at its end; zero deleted lines in numstat alone is insufficient.
6. **Rule or prompt changes.** Align changed versions across METHOD, CURRENT_RULES, CURRENT_STATE, templates and examples; archive originals and add CHANGELOG and implementation/verification records. Preserve original hypothesis registrations and append amendments. User-authorized integrity changes do not require invented statistical proof; predictive effects remain untested until the registered comparison succeeds. Never change a predictive rule on one result.
7. **Publish deliberately.** Inspect the full diff, stage only intended files by path, verify the remote and a clean state before claiming publication. Do not push over someone else's work and do not force-push. No publication is implied by a local edit.

Verify archived source length and coverage before deleting any redundant working mini, and keep unique archive bodies and audit evidence. Scientific and process failures must be visible; a green check shows only what it checks.

Owner primary-model exception (15 October 2026; narrowed by MLSCOPE-v1 to prompts 6 and 8): code still only under ml/; source-reviewed normalized market-free input and immutable output/feedback CSV/Markdown may be written under the named research/primary_predictions/ event folder, under PRIMARY_PREDICTION_PROTOCOL. Preserve source captures externally and existing issued cards; test actual primary inference and delayed sporting feedback, not just prompt wording.

Historical-source procedure: HISTORICAL_SOURCE_PROTOCOL permits game-card collection/reconciliation of reviewed normalized sporting web inputs in the named mini/primary evidence scope. It does not authorize silent shared archive/profile edits or historical card rewrites. Archive repairs use prompt7 with preserved originals and field-level provenance.

**Research retention before model availability (RETAIN-v2).** Retain every identified researched event under its stable local event key regardless of ML/runtime/baseline/calibration availability; use RESEARCH_ONLY_NO_MODEL and an honest execution disposition when needed. Prompts 1–3 neither assign nor reserve canonical P-IDs. Prompt 1 appends the full research card to the mini, updates its intake/footer, reads back the result and returns the complete updated Markdown document after every game request. Prompt 4 alone reconciles duplicates and assigns canonical P-IDs at import, preserving local originals and a local-to-canonical map. Verified labels remain future-development candidates; only real frozen bundles supply expert feedback. See RESEARCH_RETENTION_PROTOCOL and MINI_LOG_IDENTITY_PROTOCOL. Identity/custody/write conflicts remain real blockers; missing ML does not discard research.

Authorized retention-only import may precede settlement. Retain source cores and verify the canonical prefix/ID mapping. Code remains only in ml/; reviewed future-label candidates may be retained as text/CSV under research/training_candidates/.

**Learning pipeline (LEARN-v1).** Code stays in `ml/`. The permitted CSV/Markdown learning locations are `research/learning_store/` (append-only; written only by `python -m ml ingest add` in prompt 4 or an authorised prompt 8 change), `research/training_releases/` (immutable), `research/prospective/SHADOW_LEDGER.csv` and `research/model_registry/MODEL_REGISTRY.csv` (hash-chained, append-only) and `research/learning_status/REVIEW_LOG.csv` (append-only). Never hand-edit them; captures stay outside the repository with path and hash recorded. Run `python -m pytest ml/tests` before publishing any ML change. Continuous integration via a workflow file, and branch protection, remain owner decisions (workflow files are prohibited above). See [LEARNING_PIPELINE_PROTOCOL](LEARNING_PIPELINE_PROTOCOL.md).
