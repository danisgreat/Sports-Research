# Learning store (LEARN-v1)

Append-only, point-in-time store of researched sporting observations, written only by `python -m ml ingest` during prompt 4 (verified canonical import) or an authorised prompt 8 change. Prompts 1–3 validate their `RESEARCH_EXPORT/` with `--dry-run` against a copy. Never hand-edit these CSVs: rows of a later ingest are appended, earlier rows never change, and `INGEST_RECEIPTS.csv` (written last) defines which rows exist. Schemas, identity, quarantine and known-at rules: [LEARNING_PIPELINE_PROTOCOL](../../LEARNING_PIPELINE_PROTOCOL.md) §3.

The original LEARN-v1 release started empty. The owner-authorised CYCLE-v1 implementation now ingests independently reconciled current web captures; measured counts and source limitations are recorded in [the implementation report](../verification/forecast_cycle_2026-10-16/IMPLEMENTATION.md). These historical labels are known at current capture time, not retroactively available before their games. The retired results store is not a source. Prompt 1's executable worker uses its named mini-local store; prompt 4 idempotently ingests the preserved exports into this shared store. This handoff does not assign P-IDs during research.
