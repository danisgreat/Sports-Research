# PROMPT 1 — Research and append one individual game card

**Standing rules.** Local keys until settlement and an updated mini after every game (MINI-v2), persistent research and corroboration (EXH-v1), online history and confirmed players (HIST-v3 / AVAIL-v4), the repository fallback (REF-v1), the optional Drive drop box (DRIVE-v2) and retention (RETAIN-v3) are defined once, in [CORE](../../CORE.md) and the protocols it links. This prompt applies them and does not restate them.

**Mode:** LOCAL_MINI_STAGING · **LOCAL_WORKING_TREE** (ENV-v2). **Writes:** the reference receipt and frozen rows, the active mini under `research/active_minis/` (card, picks block, intake row and footer), the pregame freeze receipt, the adjustment-ledger rows, then a commit and push. Authority mode `LOCAL_WORKING_TREE` (CURRENT_RULES §0): record branch, HEAD SHA and any uncommitted control changes in the reading receipt. Read [CORE](../../CORE.md), this core, the one sport file for the event and the named sections of larger files. Do not settle, retrospect, change rules or assign/reserve canonical P-IDs. Use local event keys; canonical IDs are assigned only in the settlement phase. Prompt suite P-2026.10.22-v24.0 (ENV-v2 repository agent; REFMODEL-v1 reference before the card; LEDGER-v1 adjustments; PICKS-v2 linted picks; MLSCOPE-v3 freeze; contract-definition gate), new minis mini-log-10 (existing minis keep their original format).

Inputs: `Event: <participants, league/format, date/time/timezone or official event link>`; `Active mini: <repository path; default the active mini named in CURRENT_STATE>`; `Supplied contracts: <exact text/lines, or none>`; `Specific research constraints: <if any>`. The owner may simply paste a filled Upcoming game block ([GAME_REQUEST_TEMPLATE](../../GAME_REQUEST_TEMPLATE.md) says how a request is read, including a request for simulations). Treat estimated starts as estimates until verified. Locate accessible inputs first; ask only for information essential to resolve ambiguity. This core plus the one matching sport file is the complete game prompt. Open the sport file listed below and follow its seven steps.

**Reference stage and card freeze (MLSCOPE-v3).** Before any probability is typed: `python -m ml reference tier --competition C`, then the reference for that tier ([REFERENCE_MODEL_PROTOCOL](../../REFERENCE_MODEL_PROTOCOL.md) §3): `python -m ml pregame reference --game GAME.csv --lines LINES.csv --capture <fixture source .txt> --confirm-no-outcome-seen` where the declared reference is the competition's release (and, for a tier A competition whose reference is another model, to freeze the release as the challenger); or `python -m ml reference standings …` then `python -m ml reference run …` for TB-2-MD / TB-1-MD; or `reference run` without standings for the league-only baseline. Paste the printed Reference block into the card. The reference is never edited. The analyst's `p_card` (ANALYST_PRIMARY_V1) is the reference plus the logged adjustments, computed in code or by hand with every input and step printed. Use exact calculation; Monte Carlo only through the simulators the [SIMULATION_PROTOCOL](../../SIMULATION_PROTOCOL.md) table allows, with seed, N and Monte Carlo error printed. **Read model output only through this reference stage and, after the card is written and read back, the freeze block; read no other model, shadow, cycle or decision-lab output and no benchmark.** After the card is appended and read back (step 7), run `python -m ml pregame run --mini <active mini> --game GAME.csv --lines LINES.csv --capture <fixture source .txt> --confirm-no-outcome-seen`, with LINES.csv holding the card's full-game winner, handicap and total rows and each row's printed `card_p`: it re-uses an executed reference (never reruns it) and freezes the card's own final p on the same contracts, or records NOT_RUN_NO_RELEASE / NOT_RUN_STALE_RELEASE / NOT_RUN_INPUT_REFUSED. Paste the printed block below the decision block. A request too late for the full card to finish before the start gets the **fast card** first ([REFERENCE_MODEL_PROTOCOL](../../REFERENCE_MODEL_PROTOCOL.md) §7).

**Execution environment (ENV-v2).** Every prompt, 1 to 8, runs in this repository as the repository agent (`LOCAL_WORKING_TREE`), with internet access for research; every run that changes files ends with a commit and push. Details: [EXECUTION_ENVIRONMENT_PROTOCOL](../../EXECUTION_ENVIRONMENT_PROTOCOL.md). The published copy and fallback is [Sports Research on GitHub](https://github.com/danisgreat/Sports-Research/tree/main) `main` ([GITHUB_REFERENCE_PROTOCOL](../../GITHUB_REFERENCE_PROTOCOL.md)). Commit and push the updated mini, the reference and the pregame receipts before the scheduled start whenever possible: the pushed commit is the externally checkable freeze.

## Shared steps for every sport

These rules apply to every sport. At each step, apply them together with that step in the sport file; where the sport file is more specific, follow the sport file. Steps 2 and 6 have no shared rules here.

### Before step 1 — evidence standard

**Current evidence requirement:** Apply [RESEARCH_EXHAUSTIVENESS_PROTOCOL](../../RESEARCH_EXHAUSTIVENESS_PROTOCOL.md) to every decisive field, in the order of [RESEARCH_CHECKLISTS](../../RESEARCH_CHECKLISTS.md): the high-value inputs for the sport first, each timed to when it is published, then the rest. Open alternative sources whenever a required item is missing, partial, stale, inaccessible or conflicting; verify material facts with another independent source and record actual fields, source IDs/URLs, lineage, times, comparisons and attempts. Cover both sides' L5/L10/L15/L20, exact-game confirmed players/roles/bench/absences, rules, conditions, definitions, baselines/arithmetic and custody. Do not declare complete information while a required fact or corroboration is open; keep a field-level closure/next-action record in existing A3/A8/A9. Never invent data, timestamps, operator action or calculations. Preserve the stable local event key and full research even with a real documented barrier.

### Step 1 — Read and establish authority

Read [CORE](../../CORE.md), this core and the sport file; resolve controls from the local working tree and fall back to GitHub `main` for any unreadable file (REF-v1). If a required control remains inaccessible after the fallback, or an unpublished original mini is inaccessible, deliver a clearly labelled draft, not an issued append. Missing sporting data leads to explicit uncertainty or qualitative/NO_FORECAST research, not invented numbers. Print the tier (`ml reference tier`) and decide at once whether the full card can finish before the scheduled start; if not, say so and issue the fast card first.

**Strict research completion (RC-2026.10.16-v2).** Read and execute [RESEARCH_COMPLETION_PROTOCOL](../../RESEARCH_COMPLETION_PROTOCOL.md) for this sport and exact competition. Calibration, missing lineup/history, kickoff, active-mini/lease/ID conflict or write failure never ends the independent research. Complete all seven steps and A1–A9, actual source escalation, both sides' L5/L10/L15/L20 with true n, sport conditions, every supplied contract's reasoned assessment, calculation/baseline attempts and sensitivity. Give a substantive qualitative assessment for any row where numbers cannot be supported. Never fabricate a run or p_card. Include the protocol's completion matrix in A9; missing work means INCOMPLETE, not completed research. A thin intake supplement or a NO_FORECAST-only table fails this rule.

### Step 3 — Evidence, line-ups and online history

Mandatory for this sport: verify both sides' L5/L10/L15/L20 online under [HISTORICAL_SOURCE_PROTOCOL](../../HISTORICAL_SOURCE_PROTOCOL.md) and seek exact-game confirmed players/roles, bench/replacements and absences under [ROSTER_AVAILABILITY_PROTOCOL](../../ROSTER_AVAILABILITY_PROTOCOL.md). Record opened URLs, true n, source/time evidence, comparison/conflicts and unresolved fields; projections remain unconfirmed. Research online for every event, even when stored data exist; derive the windows from dated, deduplicated rows with true n; use original-language discovery where needed.

**Form windows and known-at (PR-01, R28).**
- Print each side's (team or player) L5, L10, L15, L20, season to date and league level, from dated games before the cutoff, with the true n of each window: CARD_AND_LOG_TEMPLATES §3b, ARCHIVE_USE_GUIDE online form recipe R2. Exclude online rows identified as duplicates, awarded results, forfeits or abandonments.
- The windows overlap and count as one piece of evidence. A reference built from season-to-date ratings already contains most of what they say: the shrunk L20/season rate may move the centre only as a listed adjustment with its effect row, and only for a named current mechanism; the four-window blend is printed beside it for comparison. A short-window swing is width, not a lean.
- Print web-evidence capture and source publication/availability times separately. An input whose availability before the cutoff cannot be shown is `KNOWN_AT_UNVERIFIED` and may not decide a ranked row.

### Step 4 — Distribution, expected score and comparator

**Retain the research (RETAIN-v3).** Record the full research and its ANALYST_PRIMARY_V1 probabilities (or a bounded range / UNCALIBRATED_QUALITATIVE / NO_FORECAST row with the reason) under a stable local event key, and append the card, intake row and footer to the active mini after every game request (ENV-v2). The reference stage precedes the card and the freeze follows it; canonical P-ID assignment happens only in the settlement phase (prompt 3, through the prompt-4 import). Never invent probabilities, sources or pregame timing. C21 checks that the probability method, inputs and arithmetic are disclosed; C22 checks updated-document delivery.

**Analyst primary probability (ANALYST_PRIMARY_V1, v24.0).** Build one coherent event distribution from the frozen reference and take every p_card, rank and expected value from it. 1. **Reference:** its centre (expected margin and total, or the two goal/run means), its widths and the competition's width floor ([COMPETITION_PARAMETERS](../../COMPETITION_PARAMETERS.md)); a competition with no reference starts from the league anchor (row or family prior) and shrunk team strength from the verified rows, as before, and prints `NONE` in the reference column. 2. **Adjustments:** one ledger row per confirmed fact: the fact, source, publication and retrieval times, corroboration, the quantity it moves, the [effect-table](../../EFFECT_TABLES.md) row, the signed size with its interval and the entry size (FULL, HALF or SCENARIO), and the overlap you checked ([ADJUSTMENT_LEDGER_PROTOCOL](../../ADJUSTMENT_LEDGER_PROTOCOL.md) §1). A fact with no effect row is priced as a declared low/base/high mixture with weights fixed before pricing, never as a silent shift. 3. **Width:** at or above the floor; widen, never narrow without a written exception, for early season, stale profiles or unconfirmed lineups. 4. **Convert:** recompute the one score grid (`ml.reference` or the sport file's family with PROBABILITY_TOOLKIT: §1 normal Φ with key-number handling, §2 Poisson, §3 negative binomial, §6 tennis chain, §7 cricket), writing each formula and intermediate value; handle NFL key margins 3 and 7 (empirical margin table), ice-hockey one-goal games from overtime/shootout and empty-net play, and baseball one-run games from extras and the home team's last half-inning explicitly ([simulation review](../verification/framework_change_2026-10-22-1/SIMULATION_REVIEW.md), [SIMULATION_PROTOCOL](../../SIMULATION_PROTOCOL.md)). 5. **Check** (toolkit §11): complementary rows sum to one; winner, handicap and total rows come from the same distribution; print `TEAM_BASELINE_P` (§4) and the same-line `BASELINE_P` and explain the gap with the departure ledger (§8); a p_card above 0.85 needs a named, sourced mechanism and is never clipped. Label every p_card ANALYST_PRIMARY_V1 / UNCALIBRATED_ANALYST_PRIMARY. A row that cannot be supported gets a bounded range or UNCALIBRATED_QUALITATIVE / NO_FORECAST with the reason; never an invented number.

**Pricing basis (PR-03).** When an input is labelled unfitted, stale, early-season or unconfirmed, the primary distribution is the declared mixture of its low/base/high cases (default weights 0.25/0.50/0.25, frozen before pricing). Print each row's `p_base` beside p_card. Compute at the precision actually used and print ε; rows within 2ε are a `PRECISION_TIE` (SELECTION_RULES §2). Apply any key-number, push or tie adjustment to the normalised distribution, never to one row. Print each ranked row's line distance from centre (units and z) and the card's baseline coverage with an enumerated reason for each missing BASELINE_P (SELECTION_RULES §5, §9).

### Step 5 — Candidate selection and dependence

Price every supplied contract and the declared derived universe from the one distribution; keep every supplied row's disposition. Under SEL v4 ([SELECTION_RULES](../../SELECTION_RULES.md) §0) the card prints: the probability table, the winner for both sides, the **most-likely list** (up to four rows by unrounded final p, family eligibility applied, each labelled SUPPLIED or ANALYST_DERIVED with its distance from the centre), the **information list** (rows that moved at least 0.03 from the reference, with the facts) and the abstain flag (`no strong pick` unless a ranked row reaches 0.65 or a row moved). Print the exact joint failure of the first two ranked rows from common states, or honest Fréchet bounds; a covering pair counts as one pick. Label disjoint losing sets MECHANICALLY_PROTECTED; do not claim they improve skill. Report both-decisive conditioning where pushes/voids exist.

### Step 7 — Write, audit and return

Use CARD_AND_LOG_TEMPLATES §§2–3 and §3c and MINI_LOG_IDENTITY_PROTOCOL; new minis use mini-log-10, while older minis preserve issued cores and establish a dated local-key namespace for new work. Use the active mini named in CURRENT_STATE (or the path the owner gives); if none exists, create one with prompt 2 first. Keep the decision block concise and full evidence/arithmetic in A1–A9. Write the picks block, run `python -m ml card lint --mini <mini> --key <key>` until it passes, and quote its output in A9. Insert one complete local-key card immediately before the footer, update the intake row, queues, local counts and next local key in the footer, and re-read the file so markers, keys, intake and footer agree. Then freeze the card with the pregame command (Reference stage and card freeze, above) and add its block to the card, run `python -m ml ledger add --mini <mini> --key <key>` once, and do not advance canonical state. Audit C1–C27 with actual evidence. Preserve every earlier issued block.

Before returning, complete the A9 research-completion matrix and assess every supplied row in A2/A5 even when numeric output is unavailable. Resume the existing eligible active mini rather than create a competing allocation. If its original bytes, identity or lease cannot be verified, complete the full no-ID research artifact as READ_ONLY_DRAFT / NOT_ISSUED; never reconstruct missing mini bytes or advance its footer. A completed full card draft, not just an intake note, is required.

For a duplicate or late-news correction, append a dated addendum; reforecast is NOT_PRIMARY and never changes the original grade or the frozen reference. If the active mini was not supplied or cannot be read in full, return the complete researched card as READ_ONLY_DRAFT / NOT_ISSUED without allocating an ID. Include a preserved mini copy only when its original bytes were actually read; otherwise return the separate complete no-ID artifact, never an invented mini.

**Learning record (LEARN-v2).** In A3/A8 tabulate, as Markdown, every opened prior-game row behind both sides' L5/L10/L15/L20 (date, opponent, venue, final and regulation score, source URL, published and retrieved time), the target event identity, and dated starter/bench/absence snapshots with publication time (unknown stays unknown, never healthy). Capture line-ups with publication times at every freeze: they are the only route to availability effects ([EFFECT_TABLES](../../EFFECT_TABLES.md) §4). Prompt 6 converts these tables into learning data; this prompt writes no learning-store export. Record an incomplete table as LEARN_RECORD_INCOMPLETE with its reason; it never changes p_card, ranks or the card.

**Contract definitions and comparator (RET-10 / RET-13).** Before pricing, state every supplied contract's unit (sets/games/points/goals/runs/wickets), period and settlement action (regulation/OT/SO/extras, push/void, retirement); an ambiguous supplied text is priced under each reading, frozen with both and queued as an operator-definition question, never resolved silently. Compute the same-line BASELINE_P with BASELINE_LEAGUE_V1 (SELECTION_RULES §9) from league-only inputs (`ml.reference.baseline_grid` from the competition row or family prior; `python -m ml baseline` for hockey and baseball) and print it beside p_card, or its exact missing reason. Record the reference and the freeze dispositions (EXECUTED, BASELINE_ONLY, NOT_RUN_NO_RELEASE, NOT_RUN_STALE_RELEASE, NOT_RUN_INPUT_REFUSED or FAILED) with their receipt paths.

**Mandatory output after every game request:** (a) the reference receipt, the card, picks block, intake row and footer written into the active mini and read back; (b) the lint output and the pregame freeze block and receipt; (c) a commit and push of exactly those paths (pushed before the scheduled start whenever possible), with the commit SHA and push time reported only after remote readback; and (d) a reply that gives the probability table, the most-likely list with each line's distance, the information list, the winner, the abstain flag, the reasons and sources, the reference and the adjustments with sizes, the local key and the mini path. Never claim a save, commit or push that did not happen. Include the stable local key, canonical ID NOT_ASSIGNED (assigned in the settlement phase), timing, findings/gaps and audit evidence. An exact duplicate returns ALREADY_RECORDED or a dated addendum block, with no new ordinal. If the active mini cannot be read in full, write the complete card as a separate READ_ONLY_DRAFT / NOT_ISSUED file and allocate no local key; never invent prior contents. Settlement NOT_PERFORMED. Do not promise prediction success.
