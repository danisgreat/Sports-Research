# PROMPT 4 — CANONICAL IMPORT OF A SETTLED LOCAL MINI

**Run by:** Claude Code in a local checkout of the repository · **GitHub:** write (this import only) · **Mode:** `CANONICAL_SETTLED_MINI_IMPORT`

Import one settled local mini into the active Combined Prediction Log through the repository's transactional tools. The frozen original mini holds the forecasts, the settled mini holds the settlements and retrospectives, and their working P-IDs are kept.

**Input folder:** `<path to "Mini Settlement - P-AAA to P-BBB - YYYY-MM-DD/">`

**Allowed writes:**
- the active Combined Log, append-only and only through `log_card`;
- `research/canonical_ledger.jsonl` and `research/issued_research/`, through the same tool;
- `GAME_LOG_STATUS_CURRENT.md`, regenerated by the tool;
- one new folder `research/verification/mini_import_<P-AAA>_<P-BBB>_<YYYY-MM-DD>/`.

Do not change methodology, rules, models, earlier forecasts, probabilities, ranks, timestamps or historical grades. Do not research, predict, re-settle or re-write retrospectives.

---

## 1. Authority and clean state

1. `git fetch` and check out the current `main`. Record the HEAD SHA. The working tree must be clean apart from the input folder (which is outside the repository). On Windows, use the normal checkout with `core.autocrlf=true`, because Parts 1–5 and the root CSV are custody-hashed as CRLF.
2. Read:
   - `METHOD.md` and `CURRENT_RULES.md` (Rules T2, R1, P4 and the local-mini lifecycle);
   - `SCORING_AND_VALIDATION.md`;
   - `CARD_AND_LOG_TEMPLATES.md` (section **Local mini format `mini-log-2`**);
   - `GAME_LOG_STATUS_CURRENT.md`;
   - `research/current_combined_log.json`;
   - `research/README.md`.
3. Run the baseline checks and save their output. A failure that exists **before** the import is pre-existing; report it as such and never "fix" it by editing history:

```powershell
py -3.14 -B -m research.operations.log_card verify
py -3.14 -B -m research.operations.log_card next-id
py -3.14 -B -m research.operations.control_freeze --verify
```

If `log_card verify` reports a pending transaction, stop. Run `log_card recover` only after confirming that the prepared transaction is the expected one.

## 2. Inputs

The folder must contain:
- `ORIGINAL_MINI/<frozen>.md` (exactly one file);
- `PREDICTION_MINI_SETTLED_<P-AAA>_<P-BBB>.md`;
- `SETTLEMENT_MANIFEST.json`;
- `LOCAL_ID_MAPPING.md`;
- `UNRESOLVED_CARRYOVER.md`.

If the frozen or settled file is missing, stop. **Never rebuild forecast bytes from a summary.**

## 3. Validate and plan (read-only)

```powershell
$F = "<input>/ORIGINAL_MINI/<frozen>.md"
$S = "<input>/PREDICTION_MINI_SETTLED_<P-AAA>_<P-BBB>.md"
$O = "research/verification/mini_import_<P-AAA>_<P-BBB>_<YYYY-MM-DD>"
py -3.14 -B -m research.operations.mini_log verify-settled $F $S
py -3.14 -B -m research.operations.import_mini plan --frozen $F --settled $S --out $O
```

The plan:
- validates the frozen mini, its byte-prefix relationship with the settled mini, the settlement section, and the hashes in `SETTLEMENT_MANIFEST.json`;
- writes only `IMPORT_PLAN.json`.

Read that plan and check every classification.

Cards:

| Classification | Meaning | Action |
|---|---|---|
| `NEW_CANONICAL_EVENT` | New event; the allocator's next ID equals the working ID | Commit |
| `ALREADY_IMPORTED_EXACT` | Same event key, ID and bytes already in the ledger | Skip; consumes no ID |
| `IDENTITY_CONFLICT` | Event key already canonical under another ID or other bytes, or the ID is another event | **Stop** |
| `ID_COLLISION` | The allocator would assign a different ID (gap or overlap) | **Stop**; never renumber |

Carryovers:

| Classification | Meaning | Action |
|---|---|---|
| `CARRYOVER_REFERENCE_ONLY` | Already canonical with the same event key | Settlement addendum only |
| `SOURCE_CUSTODY_UNRESOLVED` | Not a ledger card with this event key | **Stop** |

Addenda:

| Status | Action |
|---|---|
| `TO_APPEND` / `ALREADY_COMMITTED` | Append, or skip as already present |
| `PARENT_BLOCKED` | Resolves when its card resolves |
| `SOURCE_CUSTODY_UNRESOLVED` | **Stop** |

`blocking` must be `[]`.

If it is not empty, stop. Report each blocking item and propose the reconciliation. The user decides. Do not guess, renumber, overwrite or bypass the allocator.

Cross-check the plan against the settlement:
- `new_cards` equals the cards in the mini;
- `expected_next_id_after` equals the mini footer's `Next local working P-ID`, unless a later mini has already been imported;
- the pending IDs match `UNRESOLVED_CARRYOVER.md`.

## 4. Apply

```powershell
py -3.14 -B -m research.operations.import_mini apply --frozen $F --settled $S --out $O
```

`apply` re-plans and refuses on any blocking item. It then does the following, in order and under the ledger lock:
1. Copies the inputs and packet files into `$O/inputs/`.
2. For each new card:
   - checks the allocator's next ID equals the working ID;
   - commits the **exact card block bytes** through `log_card.commit` (retained source, CRLF projection, journal, readback);
   - verifies the returned ID.
3. Appends each pre-settlement `ADDENDUM` block, in file order, under its card's ID.
4. Appends each `SETTLED` settlement block, verbatim, as a dated addendum under its card's or carryover's ID. A `PENDING_EVENT` card is imported without a settlement, and the next mini carries it.
5. Verifies the next ID and every projection, then writes:
   - `CANONICAL_IMPORT_REPORT.md`;
   - `CANONICAL_ID_MAPPING.csv`;
   - `CANONICAL_IMPORT_MANIFEST.json` (`mini_status: CANONICALLY_IMPORTED_AND_ARCHIVED`);
   - `DUPLICATE_RECONCILIATION.md`;
   - `UNRESOLVED_POST_IMPORT.md`;
   - `settlement_table.json`.

Addenda never consume an ID. Re-running `apply` is idempotent: everything already committed is detected by hash and skipped. If `apply` stops part-way, do not edit anything by hand. Run `log_card verify`, then `log_card recover` if a preparation is pending, then re-run `apply`.

Confirm each of these:
- every new card appears exactly once in the active log, with byte-exact readback;
- every settlement and addendum is attached to the correct ID;
- the next ID equals `expected_next_id_after`;
- no other canonical ID or earlier byte changed (check `git diff --stat`: only the allowed paths);
- the import report's Rule T2 numbers equal `settlement_table.json` and the local settlement report.

The control freeze excludes the active log, the ledger, the research stores, `research/verification/` and the status file, so it must still report **0 mismatches**.

Compare every failure with the baseline from step 1. Report pre-existing failures exactly, without disabling or bypassing checks. Any new failure blocks publication until it is fixed through the supported tools.

If `GAME_LOG_STATUS_CURRENT.md` shows every line changed only because of line endings, restore the repository's stored line endings before committing.
