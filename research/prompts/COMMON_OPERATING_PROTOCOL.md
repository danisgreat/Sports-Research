## 2. Preserve custody, identity and missingness

Only prompt 4 resolves and assigns new canonical IDs from current state/status plus canonical entries and dated addenda. Prompts 1–3 use stable local event keys and never reserve/advance the canonical sequence. Opening headers are historical. Search event IDs, aliases, participants, dates and doubleheader numbers across relevant records. An event keeps one stable local key and, after import, one mapped canonical ID; addenda, rollover, hypotheses and model rows consume none. Respect the mini's writer lease and frozen status; retain every request in intake with its disposition.

Issued cores, settled originals, previous parts and dated reports remain unchanged. Corrections append a timestamp, reason, parent and affected keys. Distinguish raw source bytes, imported literal core, destination prefix and committed blob; verify actual byte identity and line endings. Recheck HEAD, destination path/hash/tail and source inventory immediately before every mutation batch. Stop and re-plan a stale batch, preserving both writers' work.

Use NOT_COMPUTED/NOT_ESTIMATED/NOT_VERIFIED/UNKNOWN_DEFINITION/N/A precisely. Missing evidence is UNRESOLVED, never automatically VOID, a loss, a healthy player or zero. Preserve cancellations, partial fields, conflicts and unresolved queues. A queue records actor, exact source/field, due time/zone, final-time basis, last attempt and whether automation actually exists.

## 3. Sporting evidence and predictive calculation

**Mandatory research completion:** read [RESEARCH_COMPLETION_PROTOCOL](../../RESEARCH_COMPLETION_PROTOCOL.md). Calibration, missing sporting inputs, kickoff and mini/allocation/write blockers cannot terminate independent sporting work. Complete all applicable procedures, source escalation, form windows and every requested contract assessment, derive the ANALYST_PRIMARY_V1 probability by hand, and return the A9 evidence matrix. Separate research completion, numerical output and issuance. An incomplete search or thin NO_FORECAST supplement is not a completed result.

Apply [availability research](../../ROSTER_AVAILABILITY_PROTOCOL.md) to both sides: starters/starting role, selected bench/replacements, absences/medical/discipline, exact-event original releases, local-language escalation and final late changes. A roster/projection is not confirmation. A failed extraction is not non-publication. Complete the search before reporting a gap; preserve genuine remaining uncertainty. A release after start does not become pregame evidence.

Complete manual research without fixed countdown deadlines, continuing after start when necessary under [TIMING_RESEARCH_PROTOCOL](../../TIMING_RESEARCH_PROTOCOL.md). Freeze only the completed issued original. Keep pre-start evidence horizon, retrieval, completion, lineup check, actual issue and event-state recheck separate. CLEAN_PRE_START_INPUTS may accompany POST_START_ISSUE with independent evidence/no outcome exposure; score it separately, never as a pre-start-issued prospective card. Use known-at sporting inputs only. Prior dated results, current rosters and retrospectively compiled statistics have different availability evidence. No odds, tips, fantasy or market-driven adjustments enter a manual card. Re-price changed verified inputs once, without double-counting effects already in features or form rates.

Use one supported sport/endpoint-specific event distribution for compatible contracts; derive W/P/L and supported void conditioning, expected scores, ladders and dependence from it. W/(W+L) is decisive probability, not unconditional win mass. Preserve allowed draws, integer pushes, legal support, approximation/tail/error limits and genuine covariance. Do not invent a simulation, fitted model or exact joint. Cross-family dependence without a joint model gets bounds.

Freeze the candidate recipe before pricing; preserve every supplied contract's disposition; from v24.0 the card prints a probability for every supplied contract, the winner, a most-likely list ordered by unrounded p_card with declared tie-breaks, an information list and an abstain flag (SELECTION_RULES §0). User-supplied lines remain reference under current P4; the separate supplied-first root draft is not active authority. Retain all original primary ranks and up to four supported candidates. Keep shadow alternatives separate. Compute a frozen league-only baseline on identical line/endpoint or state the precise missing reason. Higher win rates from easier line construction are not incremental predictive skill.

## 4. ML/RL evidence gates

These gates apply to every model comparison and promotion decision (prompts 6 and 8; MLSCOPE-v3). The reference stage and the freeze in prompt 1 only freeze rows; they decide nothing. Passing tests establishes specified mechanics. Historical development, source admission, numerical coherence, calibration, prospective predictive advantage and operational readiness are separate statuses. A SHADOW_CANDIDATE is not a qualified card model. An automatic data check is not field-owner certification, and a historical label-tier claim requires row/field evidence.

Before using a sporting shadow for a prospective comparison, require exact model/scope/version, data and code/config identities, independently frozen pre-start receipt, unchanged forecast bytes, correct event/contract/endpoint, actual timing evidence, compatible source inputs and resolved settlement revision. A local receipt file or git timestamp alone does not prove pregame publication. Invalid/missing gates exclude it from prospective scoring with a reason; retain the request and diagnostic inventory. No backfilled baseline, shadow or issue time can enter a future cohort.

Maintain TRAIN → chronological TUNE/OOF → independent CALIBRATE → untouched TEST → FUTURE SHADOW separation. Historical archive exposure stays disclosed. Predeclare the estimand, practical effect, precision/power/dependence, inclusion, multiplicity and stop rule before confirmatory collection. Numerical floors or a confidence interval containing an ideal value are not qualification. Refit/recalibration creates a governed new artifact or belongs to a predeclared refit procedure; it never edits issued probabilities.

The decision lab is paper research under CURRENT_RULES §5a. The existing staking RL is not a game-outcome forecaster; the separate sports-only full-information mixture weights the forecasting experts under PRIMARY_PREDICTION_PROTOCOL. The staking lab aggregates, CLV, stake choices and market comparisons never influence card inputs, ranks, widths or learning. Authorize its audit explicitly under prompt 8, outside other reading gates. Require observation/reward timing, exact behaviour probabilities, action support, comparable opportunities, payoff/cash/exposure accounting and stronger simple baselines. Missing quote/fill timestamps prevent a verified historical execution claim. A profitable simulation or negative simulation does not establish future economic performance.

## 7. Mandatory game and mini execution

**Retain the research (RETAIN-v3).** Record the full research, the reference and its ANALYST_PRIMARY_V1 probabilities (or a bounded range / UNCALIBRATED_QUALITATIVE / NO_FORECAST row with the reason) under a stable local event key, and append the card, intake row and footer to the active mini after every game request (ENV-v2). The card starts from a reference frozen before it is written (REFMODEL-v1) and a later freeze (MLSCOPE-v3) is recorded beside it; a model that cannot run is recorded as such and never blocks the card. Canonical P-ID assignment happens only in the settlement phase (prompt 3, through the prompt-4 import). Settle original contracts and keep verified outcomes for prompt 6 learning; never invent probabilities, sources or pregame timing. C21 checks that the probability method, inputs and arithmetic are disclosed; C22 checks updated-document delivery.

New minis have no execution manifest: prompt 1 records the probability method, learning record and pregame shadow disposition in the card, prompt 3 settles the card and its shadow and runs the prompt-4 import, prompt 5 preserves legacy pointers, prompt 6 ingests and runs the ML/RL review, prompt 7 repairs exact-scope inputs and prompt 8 changes and tests the workshop.

**Research retention (RETAIN-v3).** Retain every identified researched event under its stable local event key. Prompts 1–2 never assign or reserve canonical P-IDs. Prompt 1 appends the full research card with its analyst probabilities, intake row and footer to the active mini after every game request (ENV-v2). Canonical P-IDs are assigned only in the settlement phase: prompt 3 runs the prompt-4 import, which reconciles duplicates and assigns them, preserving local originals and a local-to-canonical map. Verified outcomes become learning candidates in prompt 6. Identity/custody/write conflicts remain real blockers. See RESEARCH_RETENTION_PROTOCOL and MINI_LOG_IDENTITY_PROTOCOL.
