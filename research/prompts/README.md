## Reading receipt

Before dependent work, open actual files and print:

```text
READING RECEIPT
Authority: local working tree OR pinned GitHub main
Repository / branch / HEAD / read time with timezone:
Relevant working differences:
Read in full: <actual files>
Sections read: <actual paths/sections>
Current method / control / scoring / selection / formats:
Task scope / allowed writes / publication instruction:
Sport/source/archive inputs read: <actual paths and coverage, or task N/A>
Required unavailable files / contradictions / dependent steps blocked:
```

Use current local files when working inside the repository; do not pretend dirty working files equal HEAD. External agents use the same pinned published revision for all controls. Read archived issued cards under their original versions. An opening log header is historical; derive current allocation from state/status and canonical entries, including latest dated addenda. Stop allocation on genuine current disagreement, not merely an old opening snapshot.

Common requirements: no fabricated data or execution claims; explicit missingness; market blindness; frozen original cards; append-only corrections; one event/one permanent ID; unresolved evidence retained; full write/readback. If files cannot be written, return READ_ONLY_DRAFT / NOT_ISSUED complete artifacts and make no claim that IDs advanced or a mini changed.

## Release and compatibility

New minis use mini-log-6 and settlement mini-settlement-5. Existing mini-log-2 through -5 and settlement -2 through -4 stay in their original formats. New process checks expose gaps through dated addenda; they never insert absent pregame values. Historical rank/p/contract/timestamp bytes and grades remain unchanged. [Implementation roadmap](../verification/framework_change_2026-10-11-1/IMPLEMENTATION.md) distinguishes current controls from untested experiments and pending data work.
