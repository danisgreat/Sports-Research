# Synthetic local mini delivery example

These are synthetic workflow/custody fixtures, not complete sporting research, live forecasts, source receipts or canonical imports. No real ID is allocated. Read [MINI_LOG_IDENTITY_PROTOCOL](../../../MINI_LOG_IDENTITY_PROTOCOL.md).

After request 1 return the complete [updated mini after game 1](EXAMPLE_MINI_10_AFTER_GAME_1.md). After request 2 return the complete [updated mini after game 2](EXAMPLE_MINI_10_AFTER_GAME_2.md), including the identical original first card, new second card, updated intake and footer. The second result is an actual complete Markdown fixture file; no isolated-card or summary-only delivery passes C22. Neither snapshot assigns/reserves a P-ID.

An exact duplicate returns the complete current document and consumes no new ordinal. A correction appends a dated addendum with the same local key. Prompt 3 preserves these local keys and a NOT_ASSIGNED mapping. Prompt 4 later uses source/native event duplicate checks to assign real canonical IDs in current source order and preserves the local original inside its wrapper. If an original is inaccessible or a write fails, return the explicitly blocked complete separate draft under MINI-v1; do not manufacture an updated mini. Fixtures do not demonstrate a deployed import allocator or chat attachment adapter.
