# Social evidence, source cycling and metric history

9 November 2026. Practical execution guide for the existing [source-access rules](../../SOURCES.md#src-alt-v2-current-agent-access-and-competition-routes-9november2026), [social evidence standard](../../SOURCES.md#18-original-social-posts-conditional-evidence-not-a-separate-lineage), [availability protocol](../../ROSTER_AVAILABILITY_PROTOCOL.md) and [online history protocol](../../HISTORICAL_SOURCE_PROTOCOL.md). These controls govern if wording differs. This guide changes no probability method, source firewall, fixed learning-log schema or issued card.

## 1. Establish the evidence requirements first

Resolve the exact competition, season, team/player aliases, native event ID, venue timezone, scheduled start and research horizon. Make a requirement list for both sides: starters, selected bench/replacements, absences, relevant performance metrics, rules and conditions. Give every required field a requirement ID. Name its definition, unit, period and endpoint: regulation is different from overtime, a probable pitcher is different from the announced starter, and shots are different from shots on target.

Use the actual competition's [routes](COMPETITION_ROUTES.csv), then the sport/field rows in [PREGAME_SOURCES.csv](PREGAME_SOURCES.csv) and the [rejections](PREGAME_SOURCE_REJECTIONS.csv). A source that works for NBA does not establish EuroLeague, NBL, women's, youth or lower-tier coverage. A provider index is a discovery route until the exact field is opened and checked.

## 2. Use social reports with traceable authority

1. **Authenticate the publisher.** Follow the account link from the team's, league's or federation's own website, or verify its organisation-controlled domain identity. Save that ownership link. A badge, similar username or follower count is insufficient. A named reporter needs an identifiable publication/employer and an attributable report; record whether it is firsthand or a relay.
2. **Check access before opening.** Audit the exact post, video, image/document host and any redirect with the current eight-token procedure. Do not use syndication, an embed endpoint, a cache, a mirror or a changed user agent to retrieve a blocked post. Instead seek the team's own web release, official team-sheet PDF or another publisher's original reporting of the field. Shared facts retain their common lineage.
3. **Read the original content.** Save the original post/video URL and ID, account, exact match, publication/edit/retrieval times with offsets, a faithful sporting extract and capture hash. Read the full image/team sheet at legible resolution. For a video, retain the relevant video timestamp and checked words; auto-captions need checking against the audio. A thumbnail, search snippet, secondhand screenshot or AI summary is a lead, not verified evidence.
4. **Classify the claim precisely.** Distinguish named game squad, starting role, bench, emergency/reserve, active/inactive, injury, illness, suspension, rest, personal absence, omission and unknown reason. Separate an official selection from a reporter's projection, training observation, probable participant or speculative return date. Training/photos/silence do not establish fitness. A player can be active without a confirmed workload.
5. **Check scope and corroboration.** A club can announce its own team; it cannot certify the opposition or every league injury. Open the competition team sheet/eligibility record and an independent report where required. A club post, its club article and ten reports quoting it are one upstream source. Conflicting or uncorroborated claims stay explicit; do not average or silently choose the most convenient one.
6. **Recheck at the real release window and before issue.** Use the competition's actual announcement convention. Recheck scratches, replacements, withdrawals and corrected graphics for both sides. A later correction gets a dated observation/addendum, never a rewritten pregame record. Unknown publication time cannot prove pre-cutoff knowledge.

Record these observations with [SOCIAL_EVIDENCE.csv](../prompts/templates/SOCIAL_EVIDENCE.csv), linked to the existing [source attempt ledger](../prompts/templates/SOURCE_SEARCH_ATTEMPTS.csv). Map verified observations into the existing learning-log availability vocabulary without adding columns to its fixed files. Preserve richer distinctions and uncertainty in the evidence appendix.

**Current access observation:** the 9 November follow-up rejected the tested X, Instagram and Facebook paths under the union of eight agent tokens. The tested YouTube channel and Bluesky root allowed policy checks and HTTP retrieval, but the readable pages did not establish a game-specific claim. That is not a test of every platform URL, official account, post, transcript or API. [Checks](../verification/source_sweep_2026-11-09-1/social_access/SOURCE_ACCESS_AUDIT.csv), [retrievals](../verification/source_sweep_2026-11-09-1/social_access/RETRIEVALS.csv). Earlier September platform-success tables are historical observations, not current permission.

Social is useful for selections, medical/disciplinary updates, withdrawals, schedule/venue changes and attributable coach news. Historical statistics should normally come from dated match records and compatible structured tables. An official graphic is a statistic source only when its event, metric definition, period and arithmetic can be checked; it does not supply an entire L20 series by implication.

## 3. Cycle sources by the missing field

For each requirement, follow this loop:

```text
exact event + field definition
  -> owner match sheet / official feed / timed injury report
  -> team or federation's own release / PDF / original permitted social report
  -> permitted structured provider covering this competition and metric
  -> named reputable local or specialist reporting
  -> local-language searches, aliases, season/round/date/opponent, archive pagination
  -> compare compatible observations, record remaining limitation
```

Audit each exact URL first. Only ALLOWED or NO_RULES_FILE proceeds; a pass establishes neither technical availability nor accuracy. When a permitted raw page is unreadable, try its normal supported rendering or a separately published official PDF, record both outcomes, and stop that route if it still fails. Follow only actually discovered/documented public links, not guessed private APIs. Access restrictions are never bypassed.

Record every attempted route, query/navigation, time, access disposition, fields found, missing/conflicting values, collector relation and next action in SOURCE_SEARCH_ATTEMPTS. Distinguish policy refusal, authentication/challenge, technical extraction, stale/wrong event, wrong definition and non-publication. A failed site does not imply that the field is absent, zero or unpublished.

Continue other required fields while waiting for a selection release. Once a field has sufficient compatible evidence, stop repeating equivalent copies; pursue missing corroboration and the other fields. Use bounded retries for transient technical faults. Do not keep hitting a blocked source. An unresolved field ends as NOT_VERIFIED, UNAVAILABLE, CONFLICTING or KNOWN_AT_UNVERIFIED with its real reason, attempts and next check. Research completeness and factual confirmation are different checks.

A newly useful route gets its exact competition/field, owner and collector, raw capture/hash, publication/retrieval clocks, freshness, limitations and recheck timing recorded. On card tasks keep it in that card's permitted evidence scope; source/framework tasks may promote it to the shared register after review. Do not promote a whole website from one successful page.

## 4. Build L5/L10/L15/L20 for every researched metric

1. **Specify the metric plan before seeing outcomes.** List the metrics needed for the supplied contracts and sport checklist, for both sides. Define units, numerator/denominator for rates, period, endpoint, competition/format scope and any surface, venue or innings-role restriction. Record unavailable and inapplicable metrics too. Do not replace xG with goals, pace with PPG, regulation with overtime-inclusive totals or observed lineups with a projection without an explicit separate label.
2. **Create the event spine.** Open the team's/player's actual results and pagination, newest first, seeking the last 20 eligible completed games before the horizon. Record native ID, event time, opponent, home/away/neutral, competition, season, endpoint and completion status. Deduplicate postponed/rescheduled listings, aliases and source copies. Exclude awarded/forfeited/abandoned rows under the controlling history rules; retain the exclusion reason. Preserve declared cross-season continuity and distinguish genuinely short history from incomplete collection.
3. **Freeze membership before filling metrics.** L5/L10/L15/L20 are nested slices of that one eligible event list. If only eight eligible games exist, memberships are 5/8/8/8. If 20 games exist but a metric is available in eight, the requested L20 still contains 20 games and has only eight observed metric values. Do not slide backwards until 20 convenient nonmissing observations have been found. Any other population is a separately named sensitivity.
4. **Fill game-level metrics from actual records.** Use box scores, period/innings tables, team sheets, play-by-play or compatible documented feeds. Retain source URL, source field, raw value, units, endpoint, publication/update/known-at/retrieval times, capture hash and collector. Use [METRIC_GAME_OBSERVATIONS.csv](../prompts/templates/METRIC_GAME_OBSERVATIONS.csv) for the companion evidence; multiple sources are observations of one event, not extra games. Derived values need the inputs and arithmetic.
5. **Cycle gaps and validate values.** Apply section 3 separately to each missing metric/game. Check score and period sums, units, orientation, duplicate IDs, exact competition and period, missing-value tokens and suspicious zero defaults. Match material fields to independent evidence where available. Preserve conflicts and reject incompatible providers. A currently accessible historical page supports research now; it cannot establish that its contents were public at an earlier forecast date.
6. **Aggregate the actual nested windows.** For every side/metric/window print requested N, eligible games, observed n, missing/conflicting n, date range, source observations, denominator and definition. Mean counts use observed compatible games and disclose partial coverage; pooled rates use sum(numerators)/sum(denominators), not an unweighted mean of percentages. N=0 is missing, never zero performance. Never fill an absent team metric with a league average. Do not merge provider-specific xG or other proprietary definitions without demonstrated compatibility.
7. **Publish the coverage matrix.** Use [WINDOW_COVERAGE.csv](../prompts/templates/WINDOW_COVERAGE.csv). Every planned metric has four rows per applicable side, even when unavailable. A report such as `corners L20: 17/20 observed, 2 not published, 1 conflict` is useful and honest; `L20 verified` is false. Keep a season and exact-league comparison separate. Overlapping windows are one body of evidence, not four independent votes.
8. **Read back and retain.** Check A3/A8/A9 against the metric plan, event spine, attempts and coverage matrix. Write the existing learning-log PRIOR_GAMES, FEATURES and AVAILABILITY files in their fixed schemas, with supplemental metric/window evidence in the card's named evidence scope. Add only justified pre-start feature values; richer after-start research stays in a dated retrospective appendix. Run the existing learning-log check, card lint and freeze procedure, then scoped commit/push under prompt 1. Missingness never alters an issued probability or creates a pregame receipt retrospectively.

**Enforcement limit:** the current `learning-log check` enforces required dictionary features, file schemas, status vocabulary and timing checks. It does not independently prove complete pagination, every metric's 20-game membership, source truth, a completed independent-source search or arithmetic linking every aggregate to these companion tables. The metric plan and matrix are explicit A9 review evidence; the new templates do not add an automatic validator. A stronger automated gate would be a separate prompt-8 code change, tested on missing games, conflicting providers and cutoff leakage. Do not describe the present check as that gate.

## 5. Completion decision

Completion means each applicable requirement has either supported compatible evidence or a documented gap after actual alternative searches; there is no universal minimum metric-coverage percentage that makes a prediction safe or accurate. State whether a material missing field prevents numeric assessment, requires the existing uncertainty/qualitative route, or only limits a diagnostic. Never invent adjustment sizes from a new source.

Continue the existing mini rather than start one for each request. [Lifecycle and review clocks](../verification/source_sweep_2026-11-09-1/MINI_AND_LEARNING.md) explain the separate settlement, retrospective and model-decision stages. Fitted model predictions remain separate under ML-SEP-v1. Better source coverage creates better documented inputs; predictive improvement still needs frozen, same-contract prospective evidence.
