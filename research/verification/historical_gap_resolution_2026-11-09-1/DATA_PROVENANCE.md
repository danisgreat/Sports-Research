# Data provenance and transformation rules

Base: `0782afa0d55b3983d68a435b6a06c0619cd1ce07`. Operative output is `final_history_release`; the other four history directories are intermediate before/after snapshots. Raw HTTP bodies, search responses, temporary query scripts and test XML/logs remain outside the repository. Their exact paths, byte counts and SHA-256 values are in QUERY_RECEIPTS, SOURCE_CAPTURES and TEST_RECEIPT. This package contains reviewed text/CSV observations, not a pregame feature dataset.

## Source observations

For each candidate URL, apply the current eight-agent robots/content policy before opening it and gate redirects through the same policy. SOURCE_ACCESS_AUDIT records the observed rule result/time; refusal means no target page was opened. SOURCE_CAPTURES records actual retrieved bytes/hash/time or the refusal. FIELD_DECISIONS manually maps each attempt to the exact field it does or does not establish. An index, schedule, login shell, blank cell or search snippet is never converted into a final/period statistic. Shared team-result pages count as one collector. Sport24's score interpretation requires the recorded Arabic RTL team layout and LTR score CSS; it is conditional secondary evidence. Source retrieval time is not historical known-at time.

## Generated reporting and gap accounting

Run `python -m ml card-history --out <new folder>`. The implementation reads the rank ledger, reconciliation, discovered import inventories/mappings, complete canonical logs, settlement revision chains and historical overlay registries. Apply source-bound contract recovery, grade revisions, view recovery and documentary closures; retain literal fields. Compute y only for effective WIN/LOSS. Mark administrative/no-action/missing propositions and UNATTAINABLE records non-scorable; scored summaries additionally exclude diagnostic cohorts. All 54 missing propositions are now recovered; P157's four no-action labels remain excluded. Literal rank-zero/condition placeholders are classified separately from live sporting tasks.

The legacy calibration command now reads that same effective view and retains only eligible numeric-p decisive rows. Refuse unmatched settlement revisions and any source or discovery change during reporting; bind every input in the completed receipt. CALIBRATION_EFFECTIVE_ROWS is the resulting 927-row readback, not a model training release or new forecast. Existing saved model-shadow reports remain unchanged historical artifacts.

GAP_REGISTER emits one finding per applicable category, so one source row can appear more than once. Its 163 findings include terminal missing fields, documentary/no-action records, diagnostic versions, reserved-record certification, withdrawals and retirement conventions. DATA_COVERAGE_LIMITS counts missing p/baselines across literal decisive rows and must not be read as eligible-trial counts. RETAINED_CERTIFICATION_LIMITS preserves 56 prior limitations and adds current notes; it is not a new routine retry queue.

## Full-log and custody queries

LOG_FILE_INVENTORY reads complete bytes/lines from canonical log/index files, extracted issued research, active minis and text/Markdown artifacts identified by mini names or format/card markers. Deduplicate byte-identical bodies for content scanning, retaining all paths/hashes. Apply reviewed original-to-canonical heading bindings, extract URL occurrences with line hashes, and classify phase/field relevance heuristically. These associations do not certify pregame sourcing or semantically validate every old assertion. Coverage is 372 artifacts / 335 unique bodies / 638 retained IDs.

The Git custody query deduplicates reachable text/Markdown/CSV/legacy-record blobs in prediction, mini, chat, issued, settlement and status paths, then searches Drukpa/RTC identity terms. It reads 1,666 unique blobs and records 129 matches with source hashes/context. It excludes unreachable objects and unavailable external chats. A status index is not an authentic issued contract; absence from this bounded search is not proof of never-issuance.

All canonical Part 1–8 bytes and Part 9's complete base prefix are verified. Archived replaced documents/code/CSV inputs are listed in the archive manifest; executable code is retained only under `ml/`, with archived code stored as `.py.txt`. Verification compares numeric values using full local-key/contract identity for rank-zero research rows. No original issued text, learning store, release, promotion, frozen shadow or canonical ID is changed.
