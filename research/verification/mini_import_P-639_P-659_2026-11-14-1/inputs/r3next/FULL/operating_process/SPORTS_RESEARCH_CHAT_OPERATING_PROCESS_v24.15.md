## Workflow for future game requests

1. **Normalize the request (REQ-v5).** One game at a time, exact home/away/neutral venue from the official source; time in venue zone, UTC and AEDT; identify native event, format, stage, exact ML vs spread/handicap, and period/OT/retirement settlement. Preserve user's supplied line text. Default `rank_scope: SUPPLIED_ONLY`; do not rank derived lines unless user requests `all lines`. Older REQ-v4 messages remain acceptable; resolve missing metadata from field owner.
2. **Validate timing and exposure.** Record actual UTC clock, retrieval, completion and issue timestamps with time-zone offsets. Treat a source's displayed publication date and retrieval time as separate facts. Verify official reschedules; an actual post-start analysis cannot become a retrospective pre-start issuance. If outcome seen, label `OUTCOME_SEEN` and research-only. Never read live scores/plays for an intended clean pregame research lane.
3. **Source-access firewall, SRC-ALT-v3.** Check the current `research/external/access/CURRENT_ACCESS.csv`, reader-specific `READER_ACCESS` and ChatGPT do-not-open list for `ChatGPT-User`, then check the **specific path** before opening. A source blocked for this reader, with unreadable rules, expired access observation, or contrary site terms is NOT opened or bypassed with cache, mirror, proxy, translation or altered identity. Use permitted alternatives. Record `OPENED`/block/failure and actual clock. The v24.15 access snapshots are copies of dated observations, not a new audit; a new reader-access snapshot is valid only after actual checking. An owner capture is one source, not independent corroboration.
4. **Separate independent facts from repetitions.** Record original publisher/collector ID, original publication (`UNKNOWN` if undated) and actual retrieval with offset; same syndicated source is one collector. The `UNKNOWN` publication date is permitted only if authentic pre-start retrieval is evidenced; a later retrieval does not make it pregame. Confirm starters, injuries, bench, goaltenders, travel, results, L5/L10/L15/L20 with true n, league and exact competition scope. An old roster result is not a current lineup. Preserve contradictory or missing fields explicitly.
5. **Formal multi-chat work requires a *repository-created* immutable package.** Accept the supplied full commit SHA, EV2 native-identity event key, EVENT/CONTRACTS/REQUIREMENTS/ARTIFACTS manifest, manifest SHA-256, input-package SHA-256, assigned lane and packet. Never fabricate these or extract an event key from names. Standard `FULL_FIVE`: L1 availability, L2 history, L3 conditions/rules, L4 independent recheck after L1, and L5 pricing after accepted upstream returns and reviewed collectors. `REDUCED` is an explicitly declared 2–4 role mode including L5, with omission/reason and a separate evaluation cohort. `FULL_SIX` has extra L6 audit before L5, not a second priced result. Without a valid package, work as unpaired `READ_ONLY_DRAFT`, not an admitted `LANE_RETURN` or formal card.
6. **Do not break the experiment.** A valid `SINGLE_RESEARCH` comparison must be frozen before any external return/packet exposure; the FIVE comparison is frozen only after accepted FULL_FIVE returns. Never backfill an unexposed comparator, re-date a draft, claim an issue/push, or count correlated contract rows as independent sporting trials. Late, reduced, six-lane, changed-horizon and unpaired work remains separately labelled.
7. **Model, reference and calculation.** Use the current scope-specific reference, kit and parameter snapshots only when legitimately accessible, frozen and version-matched. `SR-KIT-v24.15` pricing requires a complete coherent receipt; L1–L4 provide **no probabilities**; L5 returns one numeric `PROBABILITIES` row or `UNPRICED` reason per supplied contract, preserving push mass and endpoint. Unsupported cricket simulator/tennis shock are sensitivity-only; hockey model checks do not imply calibration. Never convert an ad-hoc Poisson/normal/Wolfram calculation into a primary `p_card`. For all other chat-only calculations, label clearly *illustrative / uncalibrated / not formally issued*.
8. **Partial outputs are explicit, not silently omitted.** Accept statuses `UNSUPPORTED`, `UNAVAILABLE`, `ALL_PUSH`, `NOT_VALIDATED`; missing critical facts for a numeric contract still block formal pricing. `UNPRICED` rows have no invented zero, rank or sporting grade. Use `NO_FORECAST`/`NOT_ESTIMATED` as warranted. The 65% framework strength threshold does not qualify a model by itself.
9. **Factual/effort tracking.** Retain source-check failures, requirement statuses, discrepancies and exact consulted URLs; keep A1–A9 completion matrix with what actually ran. Owner handoff time/writer review are measured only when provided; missing effort is not zero. At settlement, use exact verified score fields, fact scorecard statuses and correct rules; independent tests do not prove prospective skill. Market-blind: no odds or betting previews as model evidence or pre-event benchmarks.
10. **Custody and local mini.** Only an authorized repository agent holding the current issuing-writer lease can write official cards, run validators/freeze, settle, assign canonical IDs via import and commit/push. Research created here is retained under separate `RESEARCH-DRAFT-##` labels in a chat-local copy; never allocate an official `LOCAL-...-G####` or canonical `P-###` for a draft.
