## Repairs and regression evidence

| Area | Defect and resulting behaviour |
|---|---|
| Cross-sport scores | int(float(...)) silently truncated fractional scores and crashed on infinity. The loader now accepts only finite nonnegative integer counts. Direct numeric scores and text scores independently check each available total/margin field, including when the other field is blank. Eleven sport categories have rejecting source fixtures. |
| Schema changes | One latest header was applied to every historical year. Each file now detects its own schema, so renamed score/participant fields are read correctly. Unsupported file schemas remain counted exclusions. |
| Event identity | Same native ID in different seasons was collapsed; conflicting duplicate finals arbitrarily kept the first row; baseball doubleheaders without IDs collapsed. Exact duplicates are counted, native IDs are scoped by season, conflicting records are all excluded, and ambiguous unidentified baseball games remain excluded rather than invented. |
| Extras | N/A/unknown text could count as positive overtime/extras; a printed 0–0 shootout score counted as a shootout. Tri-state flags retain unknowns, known zero stays negative evidence, and explicit OT/SO aliases are handled. A declared hockey tie with non-tied scores is rejected. |
| Cricket | Empty data crashed before a clear failure; counts were truncated, invalid wickets/balls accepted, and the fit window ignored competition history. Full-length/all-out innings use legal six-ball notation and the configured window. Normal archive units such as 20.0 ov are accepted. Negative/fractional/nonfinite runs, wickets over ten, illegal ball notation and innings beyond the declared cap are rejected. Runs beyond finite model support remain valid observations and receive correct CRPS/PIT instead of clipping, dropping or indexing out of range. |
| Grid ownership and coherence | Caller mutation changed a previously checked grid. Grids own their mass; malformed support, marginals, parameters and covariance are rejected. Near-zero line differences were counted both as a push and as win/loss; pushes now require exact equality and invalid sides/lines fail. |
| Tie transitions | Shifted residual tied mass could be processed again during the same loop. Only original tied mass transitions once, preserving incoming shifted states, winner proportions and residual draw mass. |
| Scoring and missingness | Missing binary outcomes became finite losses; negative/fractional multiclass indexes selected the wrong class. Invalid vectors/indexes fail, missing values stay missing, and diagnostics use only valid pairs. Floating endpoint roundoff is removed within 1e-12 without a probability floor. Empty diagnostics retain missing estimates. Constant week differences have the correct zero-width descriptive interval. |
| Chronology and fits | Equality with cutoff was allowed, intraday ages were rounded down, and invalid decay parameters/weight underflow were accepted. Training dates must strictly precede cutoff; fractional-day decay and positive weights are enforced. Failed or nonfinite count optimisations are not treated as successful fits. Parameters and degenerate baselines fail explicitly. |
| Tune/evaluate | All-failed tuning selected infinity as a best candidate; partially failed candidates could improve by omitting hard rows. Incomplete/nonfinite tune coverage cannot win. Empty evaluation is an explicit FitError; a missing total line gives missing outcome/score, not a manufactured under/loss. Unsupported engines cannot fall through to Poisson. |
| Calibration | Missing predictions poisoned fitting; unsuccessful calibrators were applied; irregular editions incorrectly required season minus one. Valid prior-edition pairs are used, failed calibrators remain unapplied, and no calibration qualification is granted. |
| Cricket reports | A numerical pass could bypass admission or pass with missing required seasons. All required seasons and both comparator checks are required; generated cards and the index use the same DATA_HOLD admission rule. ODI reports no longer claim IPL inputs. |
| Decision inputs | Duplicate joins multiplied matched events, malformed quotes created invalid signals, and extreme valid quotes fell outside fixed de-vig brackets. One-to-one identity and resolved complete inputs are required; bad quote/identity rows are counted; root brackets cover the valid domain. |
| Decision policies | Negative/invalid stakes and bad learner updates could corrupt state. Kelly/caps and learner configurations/actions/contexts/rewards are validated before mutation. Zero-bet policies return a complete unchanged-bankroll report. Signal counts and actual capped paper positions are distinguished; weekly cash and uncapped IPS reward assumptions are explicit. |
| Shadow outcomes | AWAY handicaps and UNDER totals were graded as HOME/OVER; unknown families, missing lines or unissued rows could become LOSS/WIN. Orientation is honoured; unsupported/unissued/invalid contracts stay UNRESOLVED. Supplied endpoint mismatches and missing evidence cannot resolve a row. |
| Shadow inputs | Dot-directory model IDs could escape the lane; missing/self-match fixtures and conflicting supplemental results could enter a freeze. Safe directory names, identities, integer scores, explicit hockey regulation fields, duplicate/overlap rejection and known alias routing now apply. |
| Run custody | A source receipt could identify inputs changed after loading, omit supplement/empty files or update the prediction cache before a failed completion check. All actual matching archive files are hashed; code and archive/rank/prediction/market input hashes are checked before completed output. New prediction caches get their own hash receipt. Mistyped/empty competition requests fail rather than report successful no-op execution. |

## Verification scope and preservation

The focused suite includes real source fixtures, positive edge cases and rejecting cases, plus actual generated cricket cards to check admission/season coverage. All 164 tests pass. The complete discovery inventory and fixed-parameter fit/grid checks are in COMPETITION_SMOKE.csv and SMOKE_RECEIPT.md. These smoke values are construction checks on historical data, not held-out predictions or a substitute for full tuning, rolling-origin evaluation or independent calibration. Rolling evaluation also has positive and legitimate insufficient-history fixtures for all three score-grid engines, preserving missing scores for unissued rows.

The first smoke attempt exposed the valid cricket-unit regression: 28 competitions passed and two cricket loaders yielded empty inputs. The attempt CSV/receipt and its exact generating source are retained; that source is inert .py.txt under the release archive, never active code. After correction, the final run must pass all 30 modellable routes. Verification reports the actual final result separately.

Old model reports, probabilities and receipts are preserved byte-for-byte. Their generating source and pipeline definitions differ from this implementation; current-model claims require a controlled regeneration with new receipts and source admission. The additive artifact notice invalidates current-use claims without hand-editing historical scores. Unsupported sports/competitions retain explicit NOT_MODELLED reasons. The decision lab is implemented for EPL only; generic arithmetic/learners are tested independently, but no new sport-specific RL study is invented.

External helpers are temporary Python files for smoke checks, raw hashes and copied aggregate replay reports. They fit fixed models from actual archive inputs, validate grid/contracts, inventory every route and retain code/data receipts. They do not alter source archives, create player facts, change issued records or promote a model. New snapshots and forensic source text are preserved through Git attributes without line-ending conversion. Main/push is not performed by this commit-only task.
